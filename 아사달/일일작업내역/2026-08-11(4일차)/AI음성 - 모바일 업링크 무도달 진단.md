# 모바일 업링크 무도달 진단

> [!summary] 한 줄 요약
> 모바일 무반응의 원인을 코드에서 네트워크로 확정했다 — 폰의 UDP가 서버에 전혀 도달하지 않으며(ICE checking에서 멈춤), 서버 방화벽의 소스 IP 제한이 유력해 과장님께 확인을 요청한 상태다. 프로젝트: [[AI음성]]

## 진단 타임라인

| 단계 | 실측 | 결론 |
|---|---|---|
| 필터 판정 로그 0건 + 60초 후 좀비 가드(`underflow=600`) | 프레임이 **한 개도** 안 옴 | 필터 무죄 — 판정할 입력 자체가 없음 |
| 사무실 유선(218.146.11.213)에서 aiortc 톤 송출 | `speech_started` → 전사 → 응답 완결 | 서버·OpenAI·필터 전부 정상 |

| 폰 LTE (WiFi 끔) | 동일 실패 | |

## 가설 — 서버 인바운드 UDP 소스 제한

TCP는 어디서나 되는데 UDP는 **사무실 유선에서만** 된다. 폰 WiFi는 `192.168.0.x`로 서버 LAN(`192.168.1.x`)과 대역이 달라 사설 경로도 없고, 그 공유기의 공인 IP는 사무실 회선(218.146.11.x)과 다를 가능성이 크다. 프론트에 Google STUN이 이미 있어(`webrtc_voice_module.js:76`) 후보 부재도 아니다.

가장 부합하는 설명은 **서버 방화벽이 UDP를 특정 소스 IP만 허용**하는 것이다. `firewall-cmd`는 devuser 권한 밖이라 직접 확인은 불가 — 과장님께 확인 요청 글을 올렸다 (dev.han.kr이 아니라 **dev API 서버 110.45.147.56** 기준으로 질의하도록 교정해서).

## 정정 두 건

**"방화벽 기각"은 과일반화였다.** 앞서 데스크톱 실측 하나로 방화벽 가설을 기각했는데, 그 데스크톱은 사무실 회선 하나였다. 소스가 다른 망은 검증된 적이 없었다.

**로그 부재를 프레임 부재로 읽은 판정표도 무효였다.** 로거 핀 때문에 INFO가 통째로 억제되던 시기의 해석이다. 핀 제거 후에야 판정이 성립했다.

## 부수 확정 — 실시간 사용자 자막 재료

사무실 회선 테스트에서 `conversation.item.input_audio_transcription.delta`가 **12건** 수신됐다. GA가 실시간 전사 delta를 보낸다는 확정이다. 프론트는 현재 `.completed`만 처리하므로, `speech_started`로 말풍선 자리를 잡고 `.delta`로 채우면 "답변이 사용자 프롬프트보다 먼저 뜨는" 순서 문제와 실시간 표시가 한 번에 해결된다. 프론트 담당자 전달 사항.
