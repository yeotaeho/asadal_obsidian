# 업링크 투명 탭 재설계

> [!summary] 한 줄 요약
> v4 업링크를 "발화를 쥐는 게이트+지터버퍼"에서 "그대로 통과시키고 관찰만 하는 탭"으로 재설계했다. 배포 후 재측정에서 **발화 소실 0건, 감지 지연 3.5초 → 0.3~0.5초**. 프로젝트: [[AI음성]]

## 무슨 작업

[[AI음성 - 음성 품질 A B C 실측]]이 확정한 결론 — 게이트 이득 0, 비용은 발화 소실, 게이트를 꺼도 지터버퍼의 무음 삽입이 전사를 분절 — 에 따라 업링크 경로를 갈아엎었다.

```
이전:  소스 → 지터버퍼(프리버퍼·무음삽입·재타이밍) → 게이트(버퍼·버스트) → OpenAI
이후:  소스 → 투명 탭(그대로 반환, 통계만 관찰) → OpenAI
```

`NoiseFilteredAudioProxyTrackV4`는 받은 프레임을 그 객체 그대로 반환한다. `AudioProxyTrack` 상속도 끊었다 — 상속이 되살아나면 지터버퍼 장치가 딸려 들어오므로 **비상속 자체를 테스트로 고정**했다.

## 유지한 것

| 항목 | 방식 |
|---|---|
| 다운링크 지터버퍼 | 불변 — 재생 안정화라는 본래 목적의 자리 |
| 좀비 가드 | 언더플로 600회 카운터 → recv의 **60초 타임아웃**. 로그 문구·예외 메시지는 운영 grep 연속성 위해 유지 |
| 세션 주입 계약 | 6필드 전부 수용 — 브릿지가 `**kwargs`로 펴므로 하나라도 빠지면 주입 순간 TypeError |
| 관찰 계측 | `첫 프레임 수신`, `발화 관찰 - 기준 미달(오디오는 통과)/기준 충족` — 모바일 AGC 임계값 튜닝 근거 |

## 검증

`pytest ai_voice/voice_tests/` — **dev 145 passed, main 기준 139 passed** (일발 통과). 핵심은 **객체 동일성 단언**(`got is expected`) — 버퍼링·무음 대체·복사를 한 번에 잡는다.

## 배포 후 실기 재측정

같은 스크립트·같은 음성으로 dev에서 재측정했다. B(v4 기본 = 실사용 경로)의 변화.

| 지표 | 재설계 전 B | 재설계 후 B |
|---|---|---|
| 짧은 발화 "네." | 소실 | **전사 ✓ +0.32s** |
| 인사+이름 발화 | 소실 | **완전 전사 +0.37s** |
| 회의 안내 발화 | +3.53s 꼬리만 | **완전 전사 +0.53s** |
| 작은 목소리 (노이즈 실험) | 완전 소실 | **전사 ✓ +0.40s** |
| 소음 오반응 | 0 | **0 유지** — 게이트를 걷어도 오반응이 늘지 않음 (OpenAI 방어 확인) |

v3 직행 대비 잔여 격차는 감지 지연 +0.1~0.3초(이중 트랜스코딩)다. 저SNR 발화에서 산발적 분절·왜곡이 남는데, 이제 B와 C는 물리적으로 같은 경로라 두 군의 차이는 실행 간 변동(공유 dev 부하·전송 손실·ASR 변동)이다 — 무음 삽입 같은 구조적 원인은 제거됐다.

## 부수 효과

관찰 로그가 실전 계측기로 가동된다. 이제 모바일 UDP가 뚫리면 서버 로그의 `기준 미달(오디오는 통과)` 실측치(duration/speech/ratio)로 AGC 환경의 임계값을 근거 있게 정할 수 있다 — 오디오를 잃지 않으면서.
