# 오디오 로거 핀 제거와 방향 태그

> [!summary] 한 줄 요약
> 모바일 진단을 번번이 가로막던 원인 — 로거 4개가 코드에서 WARNING으로 못박혀 있었다. 핀을 걷어내고 업/다운링크 로그를 태그로 갈라, ICE 상태가 처음으로 운영 로그에 보이게 됐다. 프로젝트: [[AI음성]]

## 무슨 작업

모바일 무반응을 조사하는데 서버 로그로 판별이 안 됐다. 원인이 겹겹이었고 커밋 네 개로 걷어냈다.

### `de01f3e` — AudioProxyTrack 핀 제거 + 방향 태그

`AudioProxyTrack.__init__`이 자기 로거를 `level=logging.WARNING`으로 고정하고 있었다. **`VOICE_CHAT_LOG_LEVEL`을 올려도 이 모듈만 무시한다.** [[AI음성 - 필터 임계값 주입과 응답 큐 경합 수정]]에서 판정 로그를 info로 올린 것이 무효였던 이유다.

업링크와 다운링크가 같은 기반 클래스를 써서 로그 문구도 똑같았다. 언더플로가 찍혀도 어느 방향인지 몰랐다. 클래스 속성으로 갈랐다.

```
[PROXY-UP]    브라우저 → OpenAI  (NoiseFilteredAudioProxyTrackV4)
[PROXY-DOWN]  OpenAI → 브라우저  (AudioProxyTrack)
```

### `5047c32` — 테스트 환경 독립화 (Codex)

"레벨이 INFO 이하"를 단언하던 테스트는 테스트 환경의 `VOICE_CHAT_LOG_LEVEL`이 WARNING이면 코드가 옳아도 실패한다. "설정을 따르는지"로 바꿨다.

### `8951ca2` — caplog 교정 + 남은 문구 태그 (Codex)

Codex가 "caplog으로는 이 로거를 못 잡는다"고 지적했고, **나는 테스트가 통과한다고 반박했다가 틀렸다.** 단독 실행하면 FAILED — 전체 실행에서 테스트 순서 덕에 우연히 통과하고 있었다. `configure_voice_logger`가 `propagate = False`로 두므로 caplog 핸들러(루트 소속)는 아무것도 못 받는다. 실측 확인: `caplog.records=0`. 로거에 수집 핸들러를 직접 다는 방식으로 고쳤다.

남은 리터럴 `[PROXY]` 4문구에도 태그를 넣었다. 특히 **좀비 세션 문구** — 모바일 조사에서 유일하게 잡히던 단서였는데 방향 표시가 없었다.

### `6d5407c` — 매니저/브릿지 핀 제거

핀 하나를 걷어냈는데도 `브리지 시작`(INFO)이 안 나왔다. 증거 사슬로 좁혔다.

- `VOICE_CHAT_LOG_LEVEL`이 systemd에도 `.env`에도 없다 (실측).
- 없으면 기본값 INFO다 (`_parse_log_level`).
- 재시작 후에도 INFO가 안 나오고 WARNING은 나온다.
- 남는 설명은 호출부 핀뿐이다.

전수 조사하니 매니저(`server_webrtc:217`)와 브릿지(`:1033`)에 같은 핀이 있었다. **`ICE 상태 변경`·`브리지 시작`이 이 두 로거 소속이다.** de01f3e에서 이 둘을 놓친 것이 내 실수다.

## 어디

| 커밋 | 내용 |
|---|---|
| `de01f3e` | AudioProxyTrack 핀 제거 + PROXY-UP/DOWN 태그 |
| `5047c32` | 로거 레벨 테스트 환경 독립화 |
| `8951ca2` | caplog 캡처 방식 교정 + 남은 문구 태그 |
