# backup 전수 대조와 유실 수정 재이식

> [!summary] 한 줄 요약
> 오리지널 v4 최종본(`backup/voice-v4`)과 복원본을 전수 대조해 유실된 운영 수정 **2건**을 발견·재이식하고, Codex 리뷰 4라운드에서 워커 수명주기 경합 2건을 추가 보강했다. 프로젝트: [[AI음성]]

## 무슨 작업

복원이 완전한지 `origin/backup/voice-v4`(tip `318c0db`)와 HEAD를 파일·함수 def·인스턴스 속성 단위로 대조했다. 지금까지 유실분이 3건(이벤트 중계, GA 가드, 좀비 스위퍼) 사후 발견됐던 만큼 전수 확인이 목적이었다.

**유실 2건을 발견했다.** 둘 다 오리지널 마지막 운영 수정(PR #585, 7/10)에서 들어온 것들이다.

| 유실분 | 원본 커밋 | 증상 |
|---|---|---|
| 브라우저 제어 JSON runtime 전달 차단 | `175d12f` | 제어 메시지가 사용자 발화로 오인 → **RAG 이중 실행 + runtime 버퍼 누적(메모리 증가)** |
| 사용자 텍스트 FIFO 직렬화 | `ae27a55` | `_deliver_text` fire-and-forget → legacy 경로에서 동시·역순 처리 가능 |

유실이 아님을 확인한 것: 토큰 사용량 반환, 이벤트 중계(+delta 로그 제외), 필터·barge-in 1초 기본값, 좀비 스위퍼, event loop 수정, orchestrator(HEAD가 상위집합). 삭제한 v4 사본 5개는 backup에서도 미사용이었음을 임포트로 재확인했다 — 오리지널 v4 orchestrator조차 v3 summarizer를 쓰고 있었다.

## Codex 리뷰

4라운드 진행, 최종 **지적 없음**.

1. **P1** 워커 종료 시 잔여 항목 방치 가능 → 지적된 경합 자체는 해당 구간에 await 가 없어 재현 불가로 판정했으나, 드레인 중단 클래스가 실재해 finally 잔여 재스폰으로 원천 차단
2. **P2** `_extract_text` 가 JSON 봉투를 벗긴 뒤 판정하면 `text` 필드를 품은 제어 메시지가 통과 → **실제 결함**, 판정을 추출 전 원문 기준으로 이동
3. **P1** 세션 재접속 시 취소된 이전 워커의 finally 가 새 워커 엔트리를 pop·재스폰 → **실제 결함** ("이전 세대의 늦은 정리" 계열), `asyncio.current_task()` 신원 확인으로 자기 것일 때만 정리
