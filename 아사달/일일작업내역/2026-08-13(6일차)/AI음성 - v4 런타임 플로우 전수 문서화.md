# v4 런타임 플로우 전수 문서화

> [!summary] 한 줄 요약
> v4 전 구간 코드를 재독해 통화 생애를 **7단계 + 예외 경로 전부**로 다이어그램화하고, 구형 필터 기준으로 낡아 있던 [[AI음성 - 런타임 플로우]] 를 현행 코드 기준으로 전면 갱신했다. 프로젝트: [[AI음성]]

## 무슨 작업

v4 파이프라인을 사용자 음성 수집부터 종료까지 추적해 7단계로 정리했다 — 세션 생성 / 미디어 경로 / 이벤트 분기 / 턴 상태기계 / LangGraph·응답 큐 / RAG tool call / 종료·정리. 각 단계의 박스마다 "뭐 하는 과정인지" 설명을 붙인 주석형 다이어그램 **7장**을 만들었고, 예외·가드 경로를 하나도 빼지 않고 담았다(등록 게이트 2, 수신 가드 3, flush 가드 4, tool 스케줄 가드 3 + 실행 가드 4, 종료 트리거 6 등).

그 내용으로 [[AI음성 - 런타임 플로우]] 를 전면 갱신했다. 8-10 판은 업링크를 지터버퍼 + 게이트 3조건 필터로 서술하고 있었는데, 8-11 재설계로 실코드는 **투명 탭**이 된 지 오래라 문서와 코드가 어긋나 있었다.

## 왜

문서가 낡으면 다음 작업(과제 2번 시간 옵션, VAD 재측정)이 폐기된 필터 파라미터 표를 근거로 삼게 된다. 실제로 구판의 "과제 2번 훅" 팁은 제거된 게이트 파라미터를 가리키고 있었다. 코드 무수정 — 읽기 전용 분석·문서화 작업이라 커밋이 없다.

## 어디

| 커밋 | 내용 | 파일 |
|---|---|---|
| 없음 | 문서화 전용 (코드 무수정) | — |

갱신 노트: `아사달/프로젝트/AI음성/AI음성 - 런타임 플로우.md`

주요 변경점.

- 4단계 구성(1a·1b·2·3·4)을 **7단계**로 재편 — 이벤트 분기·턴 상태기계·응답 큐 3개 단계 신설
- 2단계(오디오)의 구형 필터 서술 전면 교체 — 투명 탭(관찰만·60초 좀비), 다운링크 지터버퍼 **120/480ms**, `_process_utterance` 3조건·필터 파라미터 표 삭제
- GA 즉답 경로 가드, pending 큐 규율(유실 방지), FIFO 워커 자기-태스크 확인·leftover 재스폰 반영
- tool call 가드 전수(chat_id SQL 식별자 가드, `_to_top_k` OverflowError, 0건 vs 실패 -1 구분) 기록
- **휴면 경로 명시** — `_schedule_immediate_tts` 호출처 0, `_play_tts_response` 우회, `_output_relay` 죽은 코드
- 라인 참조를 2026-08-13 HEAD 기준으로 갱신 (create_answer sw:307, flush sw:2120, orchestrator orch:306 등)

## 검증

코드 실측 대조로 검증했다. `server_webrtc.py` **2,929줄** 전체, `v4/tool_call_orchestrator.py` 527줄, `voice_chat_v4_router.py` 380줄, `v4/audio_tracks.py` 투명 탭 구현을 직접 읽고 라인 번호·수치(타임아웃 0.5/1.5초, tool 5초, 유예 30초, 스위퍼 60초, 미연결 120초)를 원문과 맞췄다. `_schedule_immediate_tts` 휴면 판정은 저장소 전역 grep 으로 호출처 0건을 확인했다. 코드 무수정이라 pytest 는 해당 없음.
