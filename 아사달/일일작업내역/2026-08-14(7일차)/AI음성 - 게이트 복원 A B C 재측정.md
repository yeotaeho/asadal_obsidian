# 게이트 복원 A/B/C 재측정

> [!summary] 한 줄 요약
> P1 수정판 게이트를 dev 에 배포(PR #828)하고 4일차 방법론으로 재측정했다 — barge-in 지연은 **+3.5초 → +1.3초**로 개선됐지만, 발화 조각화·소실 구조는 그대로다(깨끗한 문장 조각 6개 중 1~2개만 도달). 프로젝트: [[AI음성]]

## 방법

[[AI음성 - 음성 품질 A B C 실측]]과 동일 — Heami TTS 합성음을 aiortc 클라이언트로 세 경로에 주입, `speech_started` 지연과 입력 전사로 계량. 모델은 gpt-realtime-2.1. 하네스는 재작성했다(4일차 스크립트 유실).

| 군 | 경로 |
|---|---|
| A | v3 직행 (기준선) |
| B | v4 게이트 기본값 (P1 수정판) — 2회 실행 |
| C | v4 게이트 무력화 (주입 100ms/0/0) |

주입 스케줄: "네."(0.2초) → "안녕하세요. 제 이름은 연세고입니다."(3.3초) → "내일 오후 세 시에 회의가 있습니다. 참석 부탁드립니다."(4.6초) → 저음량 RMS 180 (각 사이 3초 침묵).

## 결과

| 발화 | A (v3) | B (게이트) | C (무력화) |
|---|---|---|---|
| "네." (0.2초) | **+0.19초** 완벽 | **소실 (2/2회)** | +0.41초 완벽 |
| 인사+이름 (3.3초) | +0.27초 완벽 | 1회차 전부 소실, 2회차 뒷문장만 +3.1초 | +0.48초 완벽 |
| 회의 안내 (4.6초) | +0.20초 완벽 | 앞문장만 +1.3~1.5초, **"참석 부탁드립니다." 소실 (2/2회)**, 경계 왜곡("세례회가") | +0.47초 완벽 |
| 저음량 (RMS 180) | 미감지 | 미감지 | 미감지 |

저음량 미감지는 세 군 공통 — **2.1 의 서버측 VAD 기준선 자체가 RMS 180 을 발화로 보지 않는다** (4일차 A는 완벽 전사였으므로 모델 세대 차이).

## 해석

**P1 수정 효과는 실측됐다.** 4일차 B는 살아남은 발화도 감지 +3.53초(꼬리만)였는데, 이번 B는 barge-in 이 제때 발동해 **+1.3초**에 앞문장이 도달한다. 무한 폐기 루프도 사라졌다.

**게이트 본연의 소실 구조는 그대로다.** 핵심 메커니즘은 `silence_frames_to_end=3`(60ms) — 문장 사이 자연스러운 쉼마다 발화가 경계로 끊겨 조각화되고, 1초 미만 조각은 관문에서 전부 폐기된다. 그래서 3.3초짜리 문장도 통째로 사라질 수 있다. 어떤 조각이 살아남는지는 회차마다 다르다(쉼 길이가 60ms 경계에 걸쳐서).

**C−A ≈ +0.2~0.25초** — 재인코딩·지터버퍼 비용. 4일차와 같은 수준.

## 어디

측정 하네스: 스크래치패드 `ab_measure.py` (+`make_tts.ps1`). 이벤트 원본 JSONL 5개 동일 위치. 코드 변경·커밋 없음. 배포는 PR #828 머지(`app restart`)로 선행됨.

## 남는 판단

게이트를 이대로 유지하면 v3 대비 응답성·수신율 열세가 그대로 상품 품질이 된다. 선택지는 (1) 임계값 완화(특히 `silence_frames_to_end` 상향 + `min_utterance` 하향), (2) 게이트 목적 재정의(관찰 전용 복귀), (3) 현상 유지. 사용자/팀 결정 대기.
