# 음성채팅 종료 안내말 구현

> [!summary] 한 줄 요약
> 프론트가 보내던 `voice_end_msg` 를 본체가 받아주게 하고, 종료 버튼에서 안내말을 발화한 뒤 세션을 닫는 서버 계약을 만들었다. 기능: [[음성채팅 종료 안내말]]

## 무슨 작업

먼저 전달 여부를 확인했다. 프론트 payload 에는 `voice_end_msg` 가 분명히 실려 있는데 본체 전수 검색 결과 **참조 0건** — `ChatbotConfigRequest` 에 필드가 없어 Pydantic 단계에서 버려지고 있었다. [[음성채팅 첫 인사말]] 배선 전과 똑같은 상태였다.

본체는 **4줄**로 끝났다. 요청 모델에 필드 하나, SQLite 컬럼 정의 하나, 조회 SELECT 와 컬럼 리스트. 기존 봇 DB 는 `check_and_add_missing_columns` 가 자동 `ALTER TABLE` 하므로 **700여 계정 마이그레이션이 없다** — 컬럼 없는 DB 를 만들어 ALTER 후 인사말이 보존되는지 실제로 돌려 확인했다.

음성 서비스는 인사말과 대칭으로 배선했다. 브라우저가 `voice_end.request` 를 보내면 말풍선용 `voice_end.message` 를 먼저 보내고, 인사말과 **같은 응답 큐**에 종료말을 태워 발화한 뒤 `voice_end.done` 으로 종료 가능을 알린다. 큐를 공유하는 이유는 인사말과 같다 — 별도 경로로 보내면 진행 중인 응답과 동시에 나가 OpenAI 가 거부한다.

## 왜

"음성 채팅 종료 시(버튼 클릭 시) 자동으로 종료 안내말을 출력하고 음성 채팅을 종료하면 됩니다" (서창녕, 09:35). 시작만 인사하고 끝은 뚝 끊기던 비대칭을 없앤다.

## 설계에서 갈린 지점

로더를 **`SELECT *`** 로 바꿨다. 컬럼명을 지정하면 본체 배포 전 봇 DB 에서 쿼리가 통째로 죽어 **저장된 인사말까지 기본값으로 떨어진다**. 두 레포 배포 순서가 어긋나는 구간을 견디기 위한 선택이고, 그 회귀를 테스트로 고정했다.

## 검증

`pytest ai_voice/voice_tests tests` — **215 passed**. 새로 추가한 종료 관련 테스트가 아래 시나리오를 고정한다.

- 답변 도중 종료 → 진행 중이던 응답의 `done` 으로 끊기지 않는다
- 취소된 이전 응답의 지연 `done` 을 종료말 완료로 오인하지 않는다
- 발행 실패·attach 전 클릭 → 멈추지 않고 즉시 종료를 알린다
- 끼어들기 후 재클릭이 다시 먹는다
- 종료 요청 JSON 이 사용자 발화로 새지 않는다

## Codex 리뷰

`codex exec review --base origin/main` 을 **4회전** 돌렸다. 본체는 지적 없음. 음성 쪽은 P1 3건·P2 2건을 받아 4건 반영, 1건은 근거를 남기고 미채택했다.

미채택 건은 "종료말 상관을 `response.create` 의 `metadata` 로 명시하라"는 제안이다. 이 코드베이스는 **GA 모델에서 `response.create` 추가 필드가 `Unknown parameter` 로 깨진 전력**이 있어(`realtime_speaker._send_response_create` 주석), 실서버 확인 없이 넣으면 드문 경합을 막으려다 기능 전체를 깨뜨릴 수 있다고 판단했다.
