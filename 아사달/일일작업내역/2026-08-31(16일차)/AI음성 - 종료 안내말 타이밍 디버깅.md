# 종료 안내말 타이밍 디버깅

> [!summary] 한 줄 요약
> 종료 안내말이 문장 중간에서 잘리던 문제를 dev 실측 로그로 추적해, `response.done`(생성 완료)을 재생 완료로 오인하던 것이 원인임을 확정하고 고쳤다. 기능: [[음성채팅 종료 안내말]]

## 무슨 작업

배포 후 "종료 음성이 끊긴다"는 보고를 받고 세 번에 걸쳐 원인을 좁혔다. **두 번은 틀렸고 세 번째에 로그가 답을 줬다.**

첫 가설은 마이크 누수로 인한 끼어들기였다. 스피커로 나가는 안내말이 마이크에 들어가 OpenAI VAD 가 발화로 판정한다는 것. 서버에 발화 중 끼어들기 무시 가드를 넣었지만 증상은 그대로였다. **틀린 이유** — 취소 주체가 우리 코드가 아니라 GA 세션 설정의 `interrupt_response: True`, 즉 OpenAI 내부였다. 우리 가드로는 막을 수 없다.

두 번째로 마이크를 아예 끄는 프론트 수정을 넣었는데, 사용자가 이미 마이크를 끈 상태로 테스트하고 있었다고 알려줬다. 끼어들기 가설 자체가 기각됐다.

세 번째에 dev 로그를 받아 원인을 확정했다.

| 시각 | 이벤트 |
|---|---|
| 06.913 | `response.done` — **생성** 완료 |
| 09.514 | `output_audio_buffer.stopped` — **재생** 완료 |

생성 완료 뒤에도 **2.6초치 오디오가 남는다.** Realtime 은 오디오를 실시간보다 빠르게 만들기 때문이다. 그 시점에 완료를 알리고 800ms 뒤 끊었으니 문장 한가운데서 잘린 것이다.

## 두 번째 증상 — 답변 도중 종료

답변이 재생 중일 때 종료를 누르면 **이전 오디오가 끊기고 종료말도 아예 안 나왔다.** 로그에 `output_audio_buffer` 이벤트가 하나도 없었다. 같은 원인이다 — 재생이 2.6초 남은 구간에 종료말을 발행해 둘이 겹쳐 버렸다.

처음엔 이전 재생이 끝날 때까지 기다리도록 만들었으나, **종료 버튼은 "지금 끝내겠다"는 뜻**이라는 지적을 받고 반대로 바꿨다. 하던 답변을 즉시 중단하고 종료말을 낸다.

```
종료 클릭
 → response.cancel            (생성 중단)
 → output_audio_buffer.clear  (재생 중단 — 없으면 겹친다)
 → 대기 답변 폐기
 → 종료말 발행
 → output_audio_buffer.stopped → voice_end.done
```

`response.cancel` · `output_audio_buffer.clear` 를 보내는 경로가 레포에 아예 없어 새로 만들었다.

## Codex 리뷰

2건을 받아 모두 반영했고 3회전에서 지적 없음으로 통과했다.

- 생성 완료 시 `_clear_farewell` 이 상태와 함께 `response.id` 까지 지워, 재생 대기 구간에서 id 가드가 무력해지던 문제
- 종료 후 뒤늦게 끝난 RAG·tool 작업이 답변을 큐에 넣어 세션이 닫히는 중에 새 답변이 시작되던 문제

## 배운 것

`response.done` 은 **생성 완료**지 재생 완료가 아니다. WebRTC 에서 재생 완료는 `output_audio_buffer.stopped` 가 알려주며, 둘 사이 간격이 수 초다. 오디오 종료 타이밍을 다룰 때 이 둘을 구분하지 않으면 반드시 잘린다.

또 하나 — **추측으로 두 번 고쳤고 두 번 다 빗나갔다.** 로그 한 줄이 세 번째에 바로 답을 줬다. 증상을 재현할 수 없는 환경일수록 계측을 먼저 넣는 게 빨랐다.
