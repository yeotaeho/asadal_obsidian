# 음성채팅기록 녹음 저장소와 재생·삭제 엔드포인트

> [!summary] 한 줄 요약
> 2단계 녹음의 4-1 단계로, 녹음 파일의 **경로·토큰 규칙과 NAS 입출력(전용 실행기)**, 재생·삭제 엔드포인트를 테스트 우선으로 만들었다. `main` 기준 `feat/voice-record`, **306 → 328 passed**. 통화 경로 연결은 1단계가 main 에 들어간 뒤에 한다. 기능: [[음성채팅기록]]

## 무슨 작업

녹음기가 붙기 전에 "파일을 어디에 어떤 이름으로 쓰고, 누가 어떻게 읽고 지우는지" 를 먼저 고정했다.

| 구성 | 내용 |
|---|---|
| 경로 | `{db}/{봇}/{YYYYMMDD}/{세션 앞 8자}_{item_id}_qa.wav`. 세그먼트에 허용 외 문자가 있으면 녹음 안 함 |
| 토큰 | HMAC-SHA256(`VOICE_RECORD_SECRET`, 상대경로) hex 앞 32자, `compare_digest` |
| 통지 필드 | `q: {path: "voice-chat-v4/records/<상대경로>", t}` |
| WAV | 질문 + 0.3초 무음 + 답변, 모노 24kHz s16. `.part` 로 쓴 뒤 `os.replace` |
| 입출력 | 쓰기·읽기·삭제·경로 resolve 전부 전용 `ThreadPoolExecutor(2)` |
| 안전장치 | 쓰기 대기 64건 초과면 포기, 저장 루트가 없으면 만들지 않고 녹음 끔 |
| 엔드포인트 | `GET`·`DELETE /voice-chat-v4/records/{경로}?t=` → 200·204 / 403 / 404. 꺼짐·규칙 위반은 토큰 판정 전 404 |

## 왜

NAS 가 `hard` 마운트라 끊기면 입출력이 멈춘다. 이벤트 루프에서 멈추면 단일 프로세스의 모든 통화가 얼고, asyncio 기본 실행기는 DNS 조회에도 쓰여 공유하면 새 통화 연결까지 막힌다. 그래서 NAS 를 만지는 코드는 이 파일에만 두고 전용 실행기에서만 돌린다.

저장 루트를 만들지 않는 것은 compose 볼륨이 빠진 컨테이너가 컨테이너 안에 파일을 쓰고 재빌드 때 잃는 사고를 막으려는 것이다.

## Codex 리뷰 판단

P1 "저장소가 통화 경로에 연결되지 않아 녹음이 만들어지지 않는다" — **사실이지만 단계 분할의 결과라 미반영.** 연결 지점은 짝이 맺어지는 순간(`TurnLogger` 의 resolver)인데 그 코드와 폐기 알림은 아직 `feat/voice-chat-log` 에만 있다. 녹음 브랜치를 1단계 브랜치 위에 쌓지 않기로 했으므로 연결은 1단계 main 반영 뒤. 이 커밋만 배포돼도 비밀키가 없으면 꺼져 있고 엔드포인트는 404 뿐이다.
