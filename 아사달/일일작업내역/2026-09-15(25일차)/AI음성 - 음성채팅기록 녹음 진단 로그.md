# 음성채팅기록 녹음 진단 로그

> [!summary] 한 줄 요약
> dev 첫 녹음 통화에서 **짝 맺은 문답 3건에 파일이 1건**만 생겼는데 원인을 가릴 로그가 없어, 녹음기·저장소에 진단 로그를 넣었다(동작 무변경, **418 passed**). 기능: [[음성채팅기록]]

## 무슨 작업

녹음 모듈 `records.py`·`pair_recorder.py` 가 기본 로거를 써서 핸들러가 없었다. 경고는 `app_log.txt` 가 아니라 `docker logs` 에만 남았고, 정상 경로는 아무것도 남기지 않았다. 둘 다 `get_voice_logger` 로 바꿨다.

그리고 한 쌍이 파일이 되기까지 거치는 지점마다 INFO 한 줄을 남긴다. 프레임마다는 남기지 않는다.

```
세션 시작        녹음 켬 (db, bot) / 녹음 안 함 — 저장소 꺼짐 · rag_db·rag_chat_id 없음
첫 프레임        업링크·다운링크 각 1회 — 표본률·채널
speech_started   질문 시작 item, audio_start_ms, 업링크 누적 ms, 링버퍼 시작 ms
speech_stopped   질문 조각 item, 길이, 대기 목록 / 열린 구간 없이 발화 끝 / item 불일치
대기 상한         가장 오래된 조각 버림 (+ 짝 맺음 상태였으면 "파일을 잃음")
전사 도착        턴 지정 / 대상 조각 없음
재생             재생 창 열림·닫힘 — 수집 중 item, 답변 ms
짝 맺음          성공(합친 앞 조각, 질문·답변 ms) / 실패 이유(대기에 없음·저장소 꺼짐·경로 규칙)
쓰기             요청 사유(답변 끝·재생 창 닫힘)·결과(접수·거절) → 저장 완료(바이트)
끝               질문 폐기 / 멈춤·종료로 답변 끝 / 세션 종료(쓴 쌍·버린 조각)
```

## 왜

dev 통화 행 3건(59·60·61)은 모두 "음성" 칸이 비어 있었고, NAS 에는 `dbd5bae7_item_EOI9…_qa.wav` 하나(8.8초)만 생겼다. 코드상 짝 맺은 턴에 파일이 안 생기는 경우는 녹음기 예외 중단, 짝 찾기 실패, 질문 폐기, 쓰기 실패 넷이다.

인식이 흔들린 통화라 잡음·스피커 소리가 짧은 발화 구간을 여럿 만들었을 가능성이 크다. 그러면 대기 조각 상한(4개)에 밀려 질문 조각이 사라지거나 답변이 잡음 조각으로 들어간다. **코드를 다시 읽다 대기 상한이 짝 맺음 상태로 쓰기를 기다리던 조각까지 버린다는 점도 찾았다.** 이번엔 동작을 바꾸지 않고 로그로 표시만 해 원인인지 가린다.

파일이 생긴 턴도 "음성" 칸이 빈 것은 별개 문제다. 파일은 `q` 를 통지할 때만 경로가 정해지므로 브라우저까지 `q` 는 갔어야 한다. 다음 통화에서 `process_add.php` 요청 본문의 `voice_audio` 를 함께 본다.
