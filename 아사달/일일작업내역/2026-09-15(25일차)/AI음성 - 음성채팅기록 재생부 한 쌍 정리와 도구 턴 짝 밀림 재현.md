# 음성채팅기록 재생부 한 쌍 정리와 도구 턴 짝 밀림 재현

> [!summary] 한 줄 요약
> 목록 재생부를 한 쌍 녹음 기준으로 줄였고, 도구 턴 개선안을 문서로 남기는 중 **도구 조회 중 끼어들면 짝이 통화 끝까지 한 칸씩 밀리는 결함**을 재현했다. 기능: [[음성채팅기록]]

## 무슨 작업

**재생부 정리.** 설계 2차 개정(질문·답변 한 파일)에 맞춰 `chatlog.htm` 에서 TTS 모듈 로드·언어감지·답변 TTS 분기를 지우고 `<audio>` 하나로 ▶ ⏸ ■ 를 처리하게 했다(81줄 삭제, 24줄 추가). 목록 PHP 의 `answer_text` 세 줄은 되돌려 음성 필드 작업 전 원본과 바이트 동일해졌다.

**개선안 문서.** 도구 호출 전 한마디를 버리지 않고 답변 앞에 이어 붙이는 안을 추후 적용용으로 정리했다. 기록 행은 질문 1·답변 1 그대로라 텍스트 채팅과 모양이 같고, 2단계 녹음(한마디가 들어감)과 글이 일치한다. 한 질문에 답변 두 행은 저장부가 1:1 이고 토큰이 행마다 복사돼 기각 후보로 적었다.

## 왜 — 결함 발견 경위

"도구 조회 중 끼어들면 그 질문은 짝이 안 돼 제외된다" 는 전제를 코드로 확인하다가 틀렸음을 알았다.

```
턴1  질문1 → 한마디 응답(function_call) 제외 → 도구 조회
     조회 중 발화 → speech_started 가 도구 취소 → 후속 답변 없음, 질문1 대기열에 남음
턴2  질문2 → [질문1, 질문2] / 답변2(turn_id 없음) → 질문1 과 짝 ❌
턴3  질문3 → [질문2, 질문3] / 답변3 → 질문2 와 짝 ❌   … 끝까지
```

기존 e2e 도우미로 임시 테스트를 돌려 **실제 [(질문1, 답변2), (질문2, 답변3)]** 을 확인했다.

원인은 두 가지가 겹친 것이다. 발화 시작이 이전 턴 도구를 조건 없이 취소해 그 턴엔 답이 오지 않는데 `TurnLogger` 가 모르고, GA 세션의 답변은 도구 후속 답변까지 `turn_id` 가 없어 도착 순서로 짝을 맺는다. 오케스트레이터가 넘기는 `turn_id` 는 한마디 응답이 GA 자동이라 애초에 비어 있다. 테스트 도우미가 `turn_id` 를 직접 넣어 이 점을 가리고 있었다.

2단계 녹음은 질문 `item_id` 로 붙으므로, 고치지 않으면 "질문1 + 한마디" 녹음이 답변2 텍스트 행에 붙는다. **녹음 구현 전에 해결**하기로 했다.

게이트를 끈 세션은 OpenAI `semantic_vad`·`interrupt_response` 만으로 끼어들기를 판정해 잡음 `speech_started` 가 더 잦고, 잡음 한 번에도 도구가 취소돼 이 결함이 더 자주 난다.
