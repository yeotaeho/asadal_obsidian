# 잡음·본인 음성 학습·화자 구분 재검토

> [!summary] 한 줄 요약
> 18일차 "음성 잡음 제거 및 음성 학습 기능" 세션과 "음성 파일 흐름 분석" 세션을 이어받아 세 과제를 다시 조사했다. 결론은 **오디오를 서버에서 붙잡지 말고, 판정을 OpenAI 이벤트 단위(끼어들기·턴)로 옮기자**는 것이다. 실통화 탭으로 다시 재 보니 **eres2net 임계 0.6 판정은 실사용 발화 길이(중앙값 1.3초)에서 근거가 무너진다.** 코드 변경·커밋은 없다. 기능: [[음성채팅 v4 복원]]

## 무슨 작업

세 과제를 아래처럼 해석하고, 코드 확인·웹 조사 3갈래·실통화 탭 재측정을 했다. 웹 조사는 잡음 억제, 화자 인증과 TSE, 끼어들기와 턴 판정이다.

| 과제 | 해석 |
|---|---|
| 음성 잡음 | 사용자 쪽 소음이 OpenAI 로 가서 오인식·오끼어들기를 일으키는 문제 |
| 음성 학습(화자구분) | 본인 목소리 등록(지문). 업로드 배치 음성 학습의 화자 분리는 별도 경로 |
| 발화 중 사용자 구분 | b1 타인 독립 발화 무시 · b2 겹친 타인 음성 제거 · b3 등록자만 끼어들기 |

## 새로 확인한 것

| # | 내용 | 근거 |
|---|---|---|
| 1 | **화자 관문 Phase 1 은 게이트 트랙 안에만 있다.** 2.1 권장안인 "대기시간 미사용"(`UplinkAudioProxyTrackV4`)에서는 작동하지 않는다. 게이트 경로에서도 끼어들기 뒤 패스스루와 강제 정산은 화자 검사를 건너뛴다 | Chatty `backup/speaker-gate-phase1` diff |
| 2 | **실통화에서 본인 유사도가 TTS 벤치보다 훨씬 낮다.** 같은 통화 중앙값 **0.48**, 다른 통화 **0.32**. 한 발화를 반으로 나눈 조각끼리도 **0.5** 수준이다 | 아래 재측정 |
| 3 | OpenAI Realtime 에는 주 화자·화자 분리 설정이 없다. `noise_reduction` 은 near/far/null 셋뿐이고 VAD 앞에 걸린다. 최소 끼어들기 길이 옵션도 없다 | OpenAI API 레퍼런스 |

| 5 | 브라우저 `voiceIsolation` 은 ChromeOS 일부에서만 효과가 있다. Safari·Firefox 는 신호가 없고 Apple 마이크 모드는 앱이 못 바꾼다 | chromestatus, WWDC21 |

| 7 | TV·옆사람 목소리를 등록 없이 지우는 서버 설치형은 **Krisp VIVA/BVC**(계약)와 **ai-coustics Voice Focus**(연 결제 월 $135부터, 30일 체험)다. 오픈소스 SE 는 배경 화자를 못 지운다 | 벤더 문서 |
| 8 | 목소리 지문(특정인 식별 목적 임베딩)은 **민감정보** 가능성이 크다(시행령 18조 3호). 별도 동의·암호화·옵트인이 필요하다. 세션 한정도 "생성"이 처리에 포함돼 의무가 남을 수 있어 **법률 검토 대상**이다 | law.go.kr, 개인정보위 해석 |
| 9 | **ElevenLabs `scribe_v1` 은 2026-07-09 제거로 공지됐다.** 배치 STT·음성 학습이 아직 이 모델을 부른다 | ElevenLabs changelog 2026-06-08 |

## 실통화 탭 재측정

탭 녹음 6세션의 A(브라우저 원음)·C(OpenAI 수신) 파일을 Silero 로 발화를 자르고 현재 모델(eres2net zh-cn)로 임베딩했다. 사용자 발화 **45개**, AI 목소리 발화 195개다.

| 항목 | 결과 |
|---|---|
| 사용자 발화 길이 | 중앙값 **1.3초**, 최대 3.2초 |
| 본인 쌍(둘 다 1초 이상) | 같은 통화 중앙값 **0.48**, 다른 통화 **0.32** |
| 같은 발화 반쪽끼리 | 사용자 0.48, AI(TTS) 0.50 |
| 1발화 등록 | 임계 0.6 에서 본인 **95% 거부** |
| 3발화 평균 등록 | 임계 0.6 에서 본인 **55% 거부**, 0.5 에서 41% |
| 본인 대 AI 목소리 | 중앙값 0.05, 최대 0.43 (3발화 등록 시 최대 0.26) |
| 임베딩 비용 | 오디오 1초당 약 **38ms** (단일 스레드) |
| 사용자 발화 끝 → AI 음성 시작 | 게이트 미사용 세션 최소 **1.71초**, 중앙값 2.61초 |

8-18 벤치의 0.876 은 한 목소리로 합성한 TTS 라 일관성이 높았던 값이다. 실통화는 발화가 짧아 같은 사람끼리도 점수가 낮고 넓게 퍼진다. 사람 타인 분포는 이 자료에 없어 EER 은 못 구했다. 조사상 같은 언어 사칭자는 다른 언어보다 약 3배 어렵다.

## 권장 구조

오디오는 실시간으로 흘리고, 판정은 이벤트에서 한다. 붙잡는 방식은 게이트 지연·조각 폐기, 배속 되돌림, VAD 마스킹 첫 음절 손실로 이미 세 번 실패했다.

```
업링크  브라우저 ─→ 서버(붙잡지 않음) ─→ OpenAI
          └ on_frame → 링버퍼(녹음기와 같은 방식)

AI 발화 중 speech_started
  → 다운링크 볼륨 낮춤(버리지 않음)
  → 대기시간 T 이상 이어지고 (선택) 주 화자로 판정되면 response.cancel + output_audio_buffer.clear
  → 아니면 볼륨 복구

AI 대기 중 턴 확정(speech_stopped)
  → OpenAI 자동 응답은 그대로 시작
  → 병렬로 판정. 배경 화자·타인이면 response.cancel + 다운링크 비움 + conversation.item.delete
  → 첫 AI 음성까지 1.7초 이상 여유라 정상 경로 지연은 없다
```

대기시간 기능은 오디오를 잃지 않고 "AI 가 말하는 중 T 초 미만 발화는 끼어들기로 치지 않는다" 로 옮겨진다. 이것이 원래 게이트 주석이 밝힌 목적이다.

## 후속 검토 — BVC·화자 모델 후보·WS 전환

**BVC(ai-coustics Voice Focus·Krisp VIVA)는 잡음과 b1 의 1순위 후보가 맞다.** 다만 "등록된 사용자"가 아니라 "마이크 가까이의 한 사람"을 남기는 기술이다. 바로 옆 가족은 못 가르고, 스피커폰·먼 사용자는 지울 위험이 있다. 특정인을 식별하지 않아 지문 동의 부담은 작을 것으로 본다(추정). Krisp 는 WASM JS SDK, ai-coustics 는 WebAssembly 도 지원해 브라우저 배치도 가능하다.

| sherpa 화자 모델 후보 | 크기 | 학습 데이터 |
|---|---|---|
| eres2net_base (현재) | 39.6MB | 중국어 약 1만 명 |
| eres2netv2 | 71.4MB | 중국어 약 20만 명, CN-Celeb EER 3.81% |
| eres2net_base_200k | 39.6MB | 중국어 20만 명 |
| campplus_zh_en_advanced | 28.3MB | 중국어·영어, Vox1-O 1.16% |

모델은 파일만 바꿔 끼우면 되지만 병목은 발화 길이·한국어 검증·동의라 모델 교체만으로는 안 풀린다.

**WS 전환은 서버↔OpenAI 구간만이라면 권할 만하다.** OpenAI 는 서버 간 연결에 WS, 브라우저·모바일에는 WebRTC 를 권한다.

```
좋아지는 것  실시간 박자 송출이 없어져 960ms 지터버퍼 drop-oldest·무음 채우기·재타이밍이 불필요
            → 모바일 지터가 손실이 아니라 지연이 됨. 게이트 드레인 손실도 사라짐
            Opus 변환이 방향마다 한 번씩 줄어듦
            response.output_audio.delta 에 response_id·item_id 가 붙어 응답별 소리 제어가 정확
            재생을 서버가 쥐어 interrupt_response=false WebRTC 논란과 무관
할 일        _connect_realtime 재작성, output_audio_buffer.* (코드 11곳·테스트 26곳) 대체,
            conversation.item.truncate 직접 전송, 전체 세션 설정 session.update 검증
기반         미리듣기(preview/openai_realtime.py)가 이미 aiohttp WS + GA session.update 사용
주의         본체 동기화 원칙과 크게 갈라짐. 브라우저↔서버까지 WS 는 비권장
```
## 왜

## 검증

- 레포 코드는 바꾸지 않았다. 재측정은 venv 의 sherpa-onnx 1.13.7 로 오프라인 실행했다.
- 한계가 있다. 사용자 발화는 테스터 한 명으로 가정했고 라벨은 VAD 구간이다. 타인은 사람이 아니라 AI 목소리뿐이다.
