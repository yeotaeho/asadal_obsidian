# WS 전환 시 VAD·GTCRN 재평가

> [!summary] 한 줄 요약
> 서버↔OpenAI 를 WS 로 바꾸면 9-04 에 기각한 sherpa-onnx VAD 마스킹과 GTCRN 이 살아나는지 검토했다. **VAD 마스킹은 기각 유지**다. WS 는 지연만 바꾸고 어떤 프레임을 통과시키는지는 그대로라, 보존율과 잡음 차단 수치가 같다. **VAD 는 오디오를 건드리지 않는 판정 신호로 쓴다.** GTCRN 은 넣기는 쉬워지지만 위험이 그대로라 측정 전에는 넣지 않는다. 코드 변경은 없다. 기능: [[음성채팅 v4 복원]]

## 무슨 작업

9-04 PoC 보고서(`.superpowers/sdd/2026-09-04-voice-uplink-vad/task-1-report.md`)를 다시 읽고 WS 전환 가정에 대입했다.

| 기술 | 지금(WebRTC) | WS 전환 후 | 판단 |
|---|---|---|---|
| VAD 마스킹 | 기각 | 선행 지연 대신 "판정 대기 중에만 붙잡았다가 한 번에 보내기" 가 가능해 **지연만 준다**. 통과 프레임은 같다 | **기각 유지** |
| VAD 판정 신호 | 가능 | 더 깔끔. 업링크에 실시간 마감이 없다 | **채택 권장** |
| GTCRN | 넣기 까다로움 | 넣기 쉬움, SE 뒤 Opus 재압축 없음 | **측정 후 결정** |

## 왜 마스킹 기각이 그대로인가

PoC 최선 변형(문턱 0.3, 선행 500ms)은 보존 **79%/57%**, 잡음 차단 **63%/72%** 였다. 기준은 보존 90% · 소실 0 · 차단 80% 다. 발화 감지 시점부터 500ms 앞을 되살려 보내는 방식은 선행 지연 500ms 와 통과시키는 프레임이 같다. 그래서 WS 는 "항상 0.5초 늦음"을 "발화 시작 때만 늦음"으로 바꿀 뿐 두 수치는 바꾸지 못한다.

실패 원인도 첫 음절만이 아니었다. 1~2초짜리 짧은 문장의 앞뒤 음절이 잘렸고, 선행 지연을 늘리면 발화 직전 잡음까지 통과해 차단율이 떨어졌다. TEN VAD 는 sherpa-onnx 에 들어 있지만 강점은 말 끝 감지라, 말 시작 지연을 줄인다는 근거는 찾지 못했다.

## VAD 판정 신호 구조

```
브라우저 ─WebRTC─ 서버 디코드
   ├─ 원음 그대로 → 24k → input_audio_buffer.append → OpenAI
   └─ Silero VAD → 음성 확률 ─┐
OpenAI speech_started 등 ─────┴→ 끼어들기·대기시간 판정
```

OpenAI 는 원음을 전부 받으므로 첫 음절 손실이 없다. 대기시간 T 는 RMS 대신 VAD 음성 길이로 센다(RMS 는 충격음을 말로 셈).

## GTCRN 이 그대로 안고 있는 위험

| 위험 | 내용 |
|---|---|
| 인식 저하 | 음성 향상을 인식 앞에 두면 인식률이 떨어진다는 근거가 여럿이다 |
| 이중 처리 | OpenAI far_field 가 이미 잡음 제거를 한다 |
| 타인 목소리 | 말소리를 보존하도록 학습돼 TV·다른 사람 목소리를 못 지운다(BVC 몫) |
| 한국어 | 16kHz 소형 모델, 주로 영어 데이터 학습. 한국어 효과 미검증 |
| CPU | RTF 0.07(저자 수치) → 세션당 코어 약 7% |
