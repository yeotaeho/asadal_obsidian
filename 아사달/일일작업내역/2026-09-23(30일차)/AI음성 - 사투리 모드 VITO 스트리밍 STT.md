# 사투리 모드 VITO 스트리밍 STT

> [!summary] 한 줄 요약
> v4 에 `stt_engine=vito` 옵션을 붙여, 사용자 음성은 리턴제로 VITO 스트리밍이 듣고 OpenAI 는 그 전사에 음성으로만 답하게 했다. 로컬 실측에서 **발화 끝 → 턴 확정 약 1.0~1.2초**. 기능: [[사투리 인식]]

## 무슨 작업

STT 비교에서 VITO 가 이긴 것을 시연하려면 STT 만 바꾼 경로가 필요하다. v2 는 이미 "realtime 전사 → 서버 판단 → realtime 이 말하기" 구조지만, GA 세션 설정을 싣지 않아 OpenAI 연결이 없는 상태로 보이고(코드 읽기 기준) 프론트도 부르지 않는다. 그래서 v4 에 옵션으로 붙였다.

```
브라우저 음성 ─▶ 서버 ─┬─▶ VITO 스트리밍 (48kHz → 16kHz 모노, wss)
                      │      첫 결과 = 말 시작 → 기존 끼어들기 처리
                      │      최종 결과, 0.8초 조용하면 한 턴으로 확정
                      └─▶ OpenAI Realtime ◀─ input_text 사용자 메시지 + response.create
                           (침묵 트랙만 받음, turn_detection·transcription 끔)
```

화면과 턴 로그에는 VITO 전사가 `conversation.item.input_audio_transcription.completed` 모양으로 들어가 프론트 수정이 필요 없다. 켜는 방법은 요청 필드 `stt_engine: "vito"` 와 `.env` `VOICE_STT_VITO_BOTS`(봇 UUID 목록) 두 가지다. 프론트 요청 내용이 고정이라 시연은 봇 지정으로 한다. RTZR 키가 없으면 경고만 남기고 기본 경로로 간다.

## 왜

VITO 는 말 중간 쉼에서도 발화를 확정한다. 첫 실측에서 26초 발화가 "불이 나면요" 에서 끊겨, 최종 결과마다 응답을 요청하면 사용자가 쉴 때마다 AI 가 끼어든다. 최종 결과 뒤 0.8초 동안 다음 말이 없을 때만 한 턴으로 넘기도록 모았다. 그래도 고령 화자의 2~3초 쉼은 7조각으로 끊겼다. 쉼이 긴 사람에게는 어떤 턴 감지든 생기는 한계라 시연은 짧은 질문 한 문장씩 한다.

원음을 OpenAI 에 함께 보내는 B 방식은 택하지 않았다. 모델이 원음과 텍스트를 둘 다 보면 VITO 효과를 가릴 수 없다.

## 검증

- `pytest ai_voice/voice_tests -q` **427 passed**, `pytest tests -q` 8 passed
- 신규 테스트 5개: 부분 결과는 발화당 한 번만 끼어들기, 쉼으로 나뉜 최종 결과 합치기, 조용한 뒤 제출, 사용자 메시지 → 응답 요청 → 화면 이벤트 순서, 모드 결정 규칙(요청·봇 목록·키 없음)
- 실제 VITO 스트리밍에 경상 녹음 3개를 실시간 속도로 흘림: 7초 발화 2개는 한 턴으로 들어옴, 26초 발화는 7조각
- 알려진 한계: 이 모드에서는 음성채팅기록 녹음이 남지 않음(녹음기가 OpenAI 발화 경계 신호에 기댐). 응답 요청이 겹치면 그 턴은 무응답일 수 있음
- dev 배포·실통화는 아직 안 함. dev `.env` 키 추가가 먼저다
