# 사투리 지침 세션 주입과 STT 엔진 비교

> [!summary] 한 줄 요약
> 경상 사투리 300쌍을 텍스트학습에서 읽어 v4 세션 지시문에 넣었고, 방언 음성 425개로 STT 네 가지를 비교해 **VITO 만 realtime 을 이긴다**(24% → 18%, 경상 24% → 14%)는 결과를 얻었다. 기능: [[사투리 인식]]

## 무슨 작업

서울시립대 번역지침(`uos.han.kr`, `원문:번역어` 2,907쌍)을 확인하고, 같은 형식으로 경상 사투리 300쌍을 만들어 test.han.kr 텍스트학습에 저장했다. 300쌍은 우리말샘 경상 방언 중 AI Hub 경상 녹음에서 같은 뜻으로 실제 쓰인 1,608쌍을 빈도순으로 자른 것이다. "그래→그렇게" 처럼 표준어 기능어와 겹치는 것과, "버리→보리" 같은 오해 쌍 32개는 뺐다.

처음에는 전사 텍스트를 사전과 대조해 그 턴 지시문에 풀이를 붙였다(`583cddc`). 그런데 v4 GA 세션은 `create_response=True` 라 OpenAI 가 발화 끝에 바로 답하고, 전사는 그 뒤에 온다. 끼운 지점이 운영에서 실행되지 않는 코드였다. 그래서 세션을 만들 때 300쌍(약 2,457자)을 지시문에 통째로 넣는 방식으로 바꿨다(`a0e3899`).

STT 비교는 같은 425개 파일, 같은 정답으로 했다. 실제 발음 대비 CER 은 다음과 같다.

| 엔진 | 전체 | 20초 미만 | 경상 |
|---|---|---|---|
| realtime | 24% | 23% | 24% |
| **VITO** | **18%** | **20%** | **14%** |
| Qwen3-ASR-1.7B | – | 23% | – |
| CLOVA (qa155) | 39% | – | 32% |

## 왜

회장님이 보고용 시연을 요구했다. RAG 경로로 사전을 쓰는 방법부터 확인했지만 쓸 수 없었다.

```
시연 문장 30개 → decision.py 판정  needs_rag 0/30  (사투리 잡담은 검색 대상이 아님)
dev 벡터 검색 "정구지"            1건
dev 벡터 검색 문장 속 "정구지가…"   0건
```

Qwen3-ASR 는 GPU 가 없어 CPU 로 돌렸다. 처리 속도가 음성 길이와 같아(RTF 1.05) 20초 미만 전부와 긴 파일 85개만 전사했다. 정확도 비교만 유효하다.

## 어디

| 커밋 | 내용 | 파일 |
|---|---|---|
| `583cddc` | 전사 대조 → 턴 지시문 풀이 (GA 경로에서 미실행이라 다음 커밋이 되돌림) | `dialect_glossary.py`, `server_webrtc.py` |

| 로컬 | STT 비교 스크립트·결과 | `사투리/05_기법실험/vito_stt.py`·`qwen_stt.py`·`stt_비교.md` |
