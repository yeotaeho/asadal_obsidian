# OpenAI WS 전송 배포 문서와 첫 dev 통화

> [!summary] 한 줄 요약
> WS 1차가 dev 에 반영(#67)된 뒤 첫 WS 통화가 90초 동안 정상 동작했다(끼어들기 3회 처리). 배포 문서에 플래그 켜고 끄기, 로그 읽는 법, WebRTC 와 비교하는 방법을 적었다. 기능: [[OpenAI WS 전송]]

## 무슨 작업

`docs/DEPLOY.md` 에 "OpenAI 연결 WS 실험" 절을 넣었다. 플래그 파일 켜기·끄기, 사투리 세션 제외, 합성하는 버퍼 이벤트와 끼어들기 자르기, 대역폭(방향마다 약 512kbps), `[OAI-WS]` 로그 줄의 뜻을 적었다.

WebRTC 세션에는 `[OAI-WS]` 같은 통화별 요약 줄이 없다. 그래서 비교에 쓸 기존 로그도 문서에 함께 적었다.

| 보고 싶은 것 | 로그 |
|---|---|
| 세션이 어느 방식이었나 | WS 는 `OpenAI 연결 방식 WebSocket (dev 실험)`, WebRTC 는 `OpenAI Realtime Listener 브리지 준비 완료` |
| 말 끝에서 첫 답변 소리까지 | `[SPK] … 첫 답변 소리 발화끝후=…ms` (화자 판정 켰을 때, 두 방식 같은 기준) |
| 답변 소리 끊김 | `[PROXY-DOWN] Relayed … dropped=… underflow=…` |
| OpenAI 구간 패킷 품질 | `RTP 통계[OpenAI]`·`RTP 품질 경고[OpenAI]` (WebRTC 만) |

## 첫 dev WS 통화

```
05:03:34 [OAI-WS] 세션 7fd432b9 연결 model=gpt-realtime-2.1
05:05:04 [OAI-WS] 세션 7fd432b9 종료 — 보낸 음성 90.1초 · 받은 답변 76.5초 · 답변 자르기 3회
```

통화 90초 동안 업링크가 끊기지 않고 흘렀고(보낸 음성 90.1초), 답변 소리 76.5초를 받아 재생했다. 끼어들기·멈춤으로 재생 중이던 답변을 잘라 OpenAI 에 알린 것이 3회다.
