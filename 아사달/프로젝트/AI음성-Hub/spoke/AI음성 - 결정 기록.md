| **NAS 쓰기는 통화 경로에서 하지 않는다** — 질문 PCM 은 메모리에 모으고, NAS 입출력은 전용 `ThreadPoolExecutor` 에서만 | 마운트가 `hard` 라 NAS 가 끊기면 입출력이 실패하지 않고 멈춘다. 업링크 `recv` 는 이벤트 루프 위라 거기서 쓰면 단일 프로세스의 모든 통화가 언다. asyncio 기본 실행기는 DNS 조회에도 쓰여 공유하면 새 통화 연결까지 막힌다. 경로 검증의 `resolve()` 도 NAS 에 `lstat` 을 해 루프에서 하지 않는다 | `recv` 에서 WAV 직접 기록(설계 초안, 오디오 탭 방식) / `asyncio.to_thread` 기본 실행기 / `FileResponse` — anyio 공용 스레드를 잡음 / 로컬 임시 파일 후 이동 — 로컬 볼륨이 또 필요 | 〃 |
| **운영 공유 `/NAS/data` 는 반영 직전 같은 쓰기 시험을 다시 한다** | NFS 권한은 NAS 공유 폴더별 설정이라 dev 결과가 운영을 보장하지 않는다 | dev 결과로 갈음 | 〃 |
| **녹음 NAS 경로는 서버 compose 에 직접 적는다** (2026-09-15) — 위 행의 `CHATTY_VOICE_RECORD_DIR` `.env` 분리를 대체 | compose 가 gitignore 로 서버마다 따로라 경로를 바로 적어도 dev·운영이 섞이지 않는다. dev compose 에 `/NAS/data_dev/voice_records:/mnt/voice_records` 와 `VOICE_RECORD_DIR` 반영(백업 `dev/backup_20260915_before_voicerecord/`) | `.env` 치환(`${CHATTY_VOICE_RECORD_DIR:?}`) — 줄만 늘어난다 | [[AI음성 - 음성채팅기록 한 쌍 녹음으로 설계 2차 개정]] |
| **`VOICE_RECORD_SECRET` 은 서버 `.env` 에만, 서버마다 새로 생성하고 바꾸지 않는다** | compose `env_file: .env` 가 키를 컨테이너에 넣으므로 compose 에 적을 필요가 없다(OpenAI 키와 같은 방식). 외부에서 받는 값이 아니라 `openssl rand -hex 32` 로 만든다. 바꾸면 DB 에 저장된 URL 토큰이 전부 무효 | compose `environment` 에 기재 / dev·운영 같은 키 | 〃 |
