# 음성 선택과 대기시간 옵션

> [!summary] 한 줄 요약
> 음성선택 기획서 V1.9(과제 2·3)의 백엔드 준비. 파라미터·검증·미사용 분기까지 끝났고 **UI 노출과 봇별 저장이 남았다**. 서비스: [[AI음성]]

## 기획서 요약

기획서는 4장이고 두 갈래다. 사용자 화면(`chatting.htm`)의 환경설정에 **음성 설정** 항목이 붙고, 관리자 화면(`voice.htm`)에서 봇별 초기값을 정한다. 봇별 사용/미사용은 `config_chat.htm` 에서 켜고 끈다.

| 항목 | 기획서 V1.9 | 소스 대응 |
|---|---|---|
| 음성 10종 | 시더·에코·마린·애시·세이지·알로이·시머·버스·발라드·코랄 | `voice` (`RealtimeVoice` Literal) |
| 음성 초기값 | 시더 | GA 세션 기본값 `cedar` |
| 대기시간 | 0.1~2초, 0.1초 단위 | `barge_in_ms` 외 2필드 (상한은 **3초**) |
| 대기시간 초기값 | 1.2초 | `barge_in_ms=1200` |
| 대기시간 사용/미사용 | 라디오 | `wait_time_enabled` |

기획서 상한은 2초인데 서버 필드 상한은 3초다. **어느 쪽으로 확정할지 미정.**

## 무엇을 했나

프론트 연동 전 백엔드에서 막아야 할 3건을 고쳤다(`c5e754b`).

**① 기본 모델을 GA 로.** 라우터 기본값 `gpt-realtime-1.5` 는 OpenAI 가 2026-05-12 폐지한 Beta 평면 스키마 경로다. 프론트가 `model` 을 생략하면 죽은 API 로 세션을 열러 갔다. v3·v4 둘 다 `OPENAI_DEFAULT_MODEL` 로 바꿨다.

**② voice 화이트리스트.** 기획서 10종 `Literal` 로 받는다. 오타가 그대로 OpenAI 로 가면 세션 생성이 실패해 통화 자체가 안 열리므로 라우터에서 422 로 먼저 막는다. 목록은 OpenAPI 스키마에 실리므로 **별도 목록 API 를 만들지 않았다.**

**③ 대기시간 미사용.** `wait_time_enabled=False` 면 게이트 없는 `UplinkAudioProxyTrackV4` 로 갈아탄다. 끼어들기 판정은 GA 세션의 `semantic_vad` + `interrupt_response` 가 그대로 맡는다.

## 무엇이 달라졌나

프론트가 `voice` 와 대기시간 3필드만 실어 보내면 기획서 동작이 나온다. 잘못된 값은 **422 로 즉시** 걸리고, `/docs` 가 음성 목록의 단일 출처가 된다.

미사용 경로도 지터버퍼를 유지한다. 기반 클래스를 그대로 썼다면 상한이 960 에서 **320 으로 되돌아가** `26f6560` 의 모바일 지터 대응이 무효화될 뻔했다.

## 대기시간 연동 규칙

`barge_in_ms` 하나만 낮추면 안 된다. 방출 전에 3관문을 통과해야 하는데, 대기시간만 0.5초로 내리면 0.5초 시점에 정산이 돌고 관문 미달로 **발화가 폐기·리셋된다**. 무시가 아니라 말을 잃는 동작이다.

```
대기시간 T 적용 시
  스케일 O  barge_in_ms = T
            min_utterance_duration_ms = T
            min_speech_duration_ms = T/2   (현재 1200:600 = 50% 비례 유지)
  스케일 X  speech_ratio_threshold   비율은 무차원 — 같이 줄이면 관문이 사라진다
            speech_rms_threshold     음량 축
            silence_frames_to_end    발화 "종료" 판정, 다른 축
            force_flush_ms           안전장치
```

> [!warning] 하한 0.1~0.3초는 실사용에서 오탐이 터진다
> T=0.1초면 실발화 요구가 50ms 다. VAD 감도 측정에서 잡은 감지 하한(+0.2~0.3초)보다 짧아 기침·문 닫는 소리 한 번에 끼어들기가 발동한다. 셀렉트박스에 노출하는 것과 별개로, 기본 1.2초는 유지하는 편이 안전하다 — 팀장 피드백이 원래 끼어들기 오탐이었다.

## 왜

기획서를 받고 과제 2·3 의 소스 준비 상태를 확인하는 게 출발점이었다. 확인해 보니 파라미터는 이미 있었고(`barge_in_ms` 는 기본값까지 기획서와 일치), 정작 막고 있던 건 **기본값이 폐지된 API 를 가리키는 것**과 **검증 부재**였다.

## 어디

| 구분 | 내용 |
|---|---|
| 브랜치 | `feat-voice-selection-api` (`caf8066`..`c5e754b`) |
| 핵심 파일 | `ai_voice/constants.py`, `infrastructure/api/router/voice_chat_v{3,4}_router.py`, `services/voice_chat/v4/audio_tracks.py` |
| 엔드포인트 | `POST /voice/v1/voice-chat-v4/agent/session` |

## 프론트 전달 사양

```
voice: "cedar" | "echo" | "marin" | "ash" | "sage"
     | "alloy" | "shimmer" | "verse" | "ballad" | "coral"
     화면은 한글, 전송은 영문 코드. 미선택이면 필드 생략(기본 cedar)

대기시간 T초 → barge_in_ms = min_utterance_duration_ms = T*1000
               min_speech_duration_ms = T*500
대기시간 미사용 → wait_time_enabled: false

model 은 "gpt-realtime-2.1" 명시 권장 (생략해도 이제 GA 로 붙는다)
```
