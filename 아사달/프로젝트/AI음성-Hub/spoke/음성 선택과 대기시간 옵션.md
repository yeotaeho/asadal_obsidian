# 음성 선택과 대기시간 옵션

> [!summary] 한 줄 요약
> 음성선택 기획서 **V1.1(확정)** — 모델 4종 × 음성 10종 × 대기시간 옵션. 전 구간 구현에 이어 **dev 실검증으로 팝업 선택 반영을 확인**했고, 1.5 통화 전멸 원인(reasoning 필드 GA 504)을 수정했다 — dev 재머지·1.5 재확인이 남았다. 서비스: [[AI음성]]

## 기획서 — V1.1 확정판

V1.9(음성만 선택)에서 V1.1 로 개정되며 **모델 선택이 신설**됐다. 사용자 환경설정과 관리자 `voice.htm` 양쪽에 모델 SelectBox 가 붙고, "각 모델별로 지원하는 음성 목록은 동일합니다"가 명문화됐다(우리 확인 결과가 그대로 반영된 문구다). 적용 화면도 붙이기·메신저까지 늘었다.

| 항목 | 기획서 V1.1 | 소스 대응 |
|---|---|---|
| **모델 4종** | 오픈AI GPT 리얼타임 2.1 / 2.1-mini / 2.0 / 1.5 "음성", 초기값 2.1 | `model` 자유 문자열, 기본 `gpt-realtime-2.1` |
| 음성 10종 | 시더·에코·마린·애시·세이지·알로이·시머·버스·발라드·코랄, 초기값 시더 | `voice` (`RealtimeVoice` Literal), GA 기본 `cedar` |

## 무엇을 했나

**1차 (`c5e754b`) — 프론트 연동 전 함정 3건.**

① 세션 요청 기본 모델을 GA(`OPENAI_DEFAULT_MODEL`)로 — 구 기본값 1.5 는 폐지된 Beta 경로로 갔다. ② voice 를 10종 `Literal` 로 받아 오타를 422 로 선차단 — 목록은 OpenAPI 스키마가 단일 출처라 **별도 목록 API 없음**. ③ `wait_time_enabled=False` 면 게이트 없는 `UplinkAudioProxyTrackV4` 로 전환 — 지터버퍼(모바일 지터 대응 960ms)는 유지된다.

**2차 (`04205e5`) — 1.5 GA 실검증과 legacy 제거.**

기획이 1.5 를 선택지로 확정해서 GA 서빙 가능 여부를 실호출로 검증했다. **GA 엔드포인트에서 4모델 전부 201**, legacy 는 모델 무관 400. 결과대로 GA 판정 접두사를 계열 전체(`gpt-realtime`)로 넓히고 legacy 분기 4종(`_create_legacy_session`·`_build_session_legacy`·legacy 스키마)을 제거했다. 판정 확장 덕에 LangGraph 스킵·평면 update 생략 가드가 1.5 세션에도 올바르게 적용된다 — 상세는 [[AI음성 - 1.5 GA 실검증과 legacy 경로 제거]].

**3차 (`069eab4`) — dev 실검증 2건 수정.**

dev 팝업 실검증에서 두 결함을 잡았다. ① 프론트 모듈 `connect()` 가 `VoiceSettings` **존재 여부**로 분기해, 팝업 메뉴가 쓰는 `VOICE_RUNTIME_CONFIG` 선택이 묻혔다 — 값 유무 기준 병합(`_user` > `VOICE_RUNTIME_CONFIG` > `get()`)으로 교체해 **선택 반영 확인 완료**. ② **1.5 만 통화 전멸** — 세션 config 의 `reasoning` 필드를 1.5 가 못 받아 GA 가 **504 Gateway time-out** 으로 끊었다(2.x 는 201, 이분 탐색 실검증). `supports_realtime_reasoning` 판정으로 1.5 에서만 reasoning 을 떼게 했다. 상세: [[AI음성 - 음성선택 dev 검증 - 팝업 폴백과 1.5 reasoning 504 수정]].

## 무엇이 달라졌나

**기획서의 모델 4종 × 음성 10종 전 조합이 백엔드에서 동작한다.** 프론트가 `model`·`voice`·대기시간 3필드·`wait_time_enabled` 만 실어 보내면 되고, 잘못된 voice 는 422 로 즉시 걸린다. 세션 생성 경로가 GA 하나로 줄면서 두 shape 를 오가던 분기 코드가 사라졌다. dev 팝업에서 **사용자 선택 → payload → 서버 적용** 전 구간이 실검증됐다(1.5 는 재머지 후 재확인).

## 대기시간 연동 규칙

`barge_in_ms` 하나만 낮추면 안 된다. 방출 전 3관문 통과가 전제라, 대기시간만 내리면 정산 시점에 관문 미달로 **발화가 폐기·리셋된다** — 무시가 아니라 말을 잃는 동작이다.

```
대기시간 T 적용 시
  스케일 O  barge_in_ms = T
            min_utterance_duration_ms = T
            min_speech_duration_ms = T/2   (현재 1200:600 = 50% 비례 유지)
  스케일 X  speech_ratio_threshold   비율은 무차원 — 같이 줄이면 관문이 사라진다
            speech_rms_threshold     음량 축
            silence_frames_to_end    발화 "종료" 판정, 다른 축
            force_flush_ms           안전장치
```

> [!warning] 하한 0.1~0.3초는 실사용에서 오탐이 터진다
> T=0.1초면 실발화 요구가 50ms 다. VAD 감도 측정에서 잡은 감지 하한(+0.2~0.3초)보다 짧아 기침·문 닫는 소리 한 번에 끼어들기가 발동한다. 셀렉트박스 노출과 별개로 기본 1.2초 유지가 안전하다 — 팀장 피드백이 원래 끼어들기 오탐이었다.

## 봇별 저장 (본체 몫 — 미착수)

관리자 초기값은 본체 SQLite `chatbot_config` 에 저장한다(인사말 `voice_first_msg` 와 같은 패턴). 본체 3파일 수정이면 된다 — `CHATBOT_CONFIG_COLUMNS`(dict 추가만으로 자동 마이그레이션), `ChatbotConfigRequest`, `get_chatbot_config` SELECT 목록.

```
voice_model        TEXT  DEFAULT 'gpt-realtime-2.1'
use_voice_config   TEXT  DEFAULT 'Y'      -- config_chat.htm on/off
voice_name         TEXT  DEFAULT 'cedar'
use_voice_wait     TEXT  DEFAULT 'Y'
voice_wait_time    FLOAT DEFAULT 1.2
```

미해결 — 본체에 config **조회** 엔드포인트가 없다(`get_chatbot_config` 는 내부용). 관리자 화면 초기값 표시·채팅 화면 메뉴 숨김에 조회가 필요하면 신설하거나, greeting.py 처럼 서비스가 SQLite 를 직접 읽는 설계로 간다.
