3장은 대화로 전달받은 초안과 두 곳이 다르다. 멈춤을 누르면 멈춤 버튼이 "재생"으로 바뀌고 재생은 "새로운 대화 시작"이며, 음성채팅 종료는 마이크 재클릭이 아니라 **별도 종료 버튼**이다.

## ① 안내문 온오프 — 완료

플래그는 **첫·종료 각각 컬럼 2개**(사용자 결정). 인사말·종료말 배관 위에 얹었다.

```
본체   chatbot_config.use_voice_first_msg / use_voice_end_msg  (TEXT DEFAULT 'Y')
       ChatbotConfigRequest 필드 2개 → _normalize_yn (on/off → Y/N)
음성   greeting.load_voice_messages: 플래그 'N' 이면 "" 반환
       v4 라우터 if greeting: 조건 → metadata 미주입 → 발화·말풍선 동시 소멸
```

컬럼 부재·NULL 은 사용으로 취급해 본체 배포 순서와 무관하다. 프론트 키 이름은 담당자 확정 후 `AliasChoices` 로 추가한다.

종료말 미사용 봇의 종료 흐름은 **클릭 즉시 마이크 off → 서버가 `voice_end.done` 즉시 응답 → 프론트 800ms 유예 뒤 disconnect** 다. 이 분기에도 `_stop_current_speech` 를 넣어(`a17dc42`) 답변 도중 종료해도 사용 경로와 똑같이 즉시 끊긴다. 음성 브랜치 범위는 `ddda054`..`a17dc42`.

## ② 미리듣기 — Realtime 1회 합성으로 완료 (미푸시)

통화의 첫·끝 인사말은 TTS 가 아니라 **Realtime 이 `response.create` 지시문으로 직접 읽는다.** 미리듣기도 같은 모델·목소리로 문장 하나를 WebSocket 으로 1회 합성해 WAV 로 돌려준다. 저장·캐시·스트리밍은 없다.

```
ai_voice/services/voice_chat/preview/
├── __init__.py          speak_once(text, model, voice, api_key) -> WAV bytes — gpt- 접두사면 OpenAI, 아니면 UnsupportedModelError
└── openai_realtime.py   RealtimeWsSession(send/events/close) · connect · synthesize(session.update → response.create → delta 수집 → WAV)

요청  POST /voice-chat-v4/voice-preview  { text(HTML 원문 ≤2000자), model, voice }   ← model·voice 는 세션 생성과 같은 값
응답  200 audio/wav · 422 빈 문장 · 400 미지원 모델 · 502 합성 실패·타임아웃 · 503 키 없음
프론트 audio.src = URL.createObjectURL(await res.blob()); 버튼에 로딩 표시(1.7~5.0초)
```

세션 설정은 목소리·출력 포맷만 넣는 최소 설정이고 지시문은 통화 인사말 지시문의 뒷부분("다음 문장을 다른 말을 덧붙이지 말고 그대로 자연스럽게 말하라")과 같다. 타임아웃은 **15초 + 0.03초 × 문장 길이**, 소켓은 모든 경로에서 닫힌다. 벤더 분기는 향후 Gemini Live 등 다른 WS 음성 모델을 대비한 것으로, 추상 클래스 없이 시그니처만 맞춘다.

**경위.** 회장님이 "저장 시 1회 녹음해 파일로 두고 재생"을 제안했으나, 사용자 페이지가 이미 TTS 를 쓰지 않아 절약분이 없고 파일 방식은 목소리 차이를 실제 통화 첫 문장으로 옮겨 오며 미저장 문구를 들을 수 없다. TTS 판(`gpt-4o-mini-tts`, 같은 cedar 이름 지원)과 Realtime 판을 같은 문장으로 실측·청취 비교해 **목소리 차이를 확인하고 Realtime 을 택했다.** 지연은 TTS 1.6~3.8초, Realtime 1.7~5.0초로 1초 안팎 차이.

앞서 만든 TTS 판(`feat/voice-preview`)의 TTS 서비스 결함 수정 4건은 그대로 두고, 그 위에서 미리듣기 엔드포인트만 교체했다. 인증은 이 서비스의 다른 엔드포인트와 같이 없다.

## ③ 일시정지·멈춤 — 백엔드 완료

**진짜 일시정지**(멈춘 지점부터 재개)다. OpenAI Realtime·WebRTC 에 일시정지가 없으므로 **서버 다운링크 지터버퍼**(`AudioProxyTrack`)가 프레임을 쥐고 침묵을 내보낸다. 일시정지 중엔 평시 상한(960ms) 대신 3분 상한이라 재개 시 잘림이 없고, 끊기는 지점은 20ms 프레임 경계다. 클릭 후 잔여음은 브라우저 지터버퍼 0.1~0.3초뿐이다.

| 메시지 (DataChannel `oai-events`) | 서버 처리 |
|---|---|
| `{"type":"voice_playback.pause"}` | 프록시 paused. 침묵 송출, 유입 프레임은 3분 상한으로 적재. 종료말 발화 중엔 무시 |
| `{"type":"voice_playback.resume"}` | 플래그 해제, 멈춘 프레임부터 1배속. 백로그가 상한 아래로 내려갈 때까지 폐기 없음 |
| `{"type":"voice_playback.stop"}` | RAG 취소 + `response.cancel` + `output_audio_buffer.clear` + 대기 큐 폐기 + 서버 버퍼 비우기 + paused 해제. 재생 중이 아니었으면 done 즉시 |
| 서버 → `{"type":"voice_playback.done"}` | OpenAI `stopped`/`cleared` 뒤 **서버 버퍼가 빈 시점**(100ms 디바운스). 종료 절차 중엔 안 보냄 |

`voice_end.done` 도 같은 드레인 경로를 타게 바꿨다 — 프론트의 800ms 유예 없이도 종료말이 안 잘린다.

**사용자 발화 시 버퍼 비우기.** `speech_started` 가 오면 끼어들기 판정과 무관하게 서버 다운링크 버퍼를 비운다(`bd3a53c`). 재개한 백로그는 OpenAI 쪽에선 이미 끝난 응답이라 사용자가 말해도 OpenAI 는 아무것도 취소하지 않고, 서버 판정(pending·큐)도 비어 있어 옛 답변 나머지 뒤에 새 답변이 붙어 밀리는 결함이 있었다(사용자 지적). 알려진 한계 — 이때 OpenAI 대화 컨텍스트에는 옛 답변이 "끝까지 들려준 것"으로 남는다(자동 truncate 는 진행 중 응답에만 적용).

**프론트 몫.** 파일은 `chat/voice/js/webrtc_voice_module.js`(전송 3종 + 이벤트 case 2개), `modes/voice_webrtc_handler.js`(`playbackState`), `voice_mic_button.js`(버튼 2개 렌더). ⏸ 클릭 → `pause` 전송 + **마이크 트랙 off**(켜 두면 `interrupt_response` 가 붙들린 답변을 취소한다) + 선택적으로 `audio.muted` 로 잔여음 제거. ▶ → `resume` + 마이크 on + mute 해제. ⏹ → `stop` + 원복 + 버튼 즉시 비활성. 버튼 켜기는 중계된 `output_audio_buffer.started`, 끄기는 `voice_playback.done`. `response.done`·`stopped` 는 버튼 판단에 쓰지 않는다. v3 폴백 세션은 서버가 없어 메시지가 무시된다(v4 전용).

**dev 첫 테스트(2026-09-03) 결함.** `voice_end.done`·`voice_playback.done` 이 안 나가 종료가 6초 타임아웃까지 걸렸다. 원인은 `wait_drained` 가 "버퍼 공백"을 기다린 것 — OpenAI 트랙은 응답 뒤에도 침묵 프레임을 계속 보내 지터버퍼가 늘 차 있다. 재생 카운터 기반으로 교정(`c6a38f8`..`71580fb`, 브랜치 범위 `145f5c6`..`71580fb`). dev 재머지·재검증 필요. "처음부터 마이크 음소거·발화 무반응" 보고는 원인 미확인(로그 대기).

**진짜 원인은 클래스 불일치였다(`abf7a21`).** 매니저가 다운링크 프록시를 v3 사본 `AudioProxyTrack` 으로 만들고 있어 재생 제어 API 가 없었고, `_flush_downlink` 가 AttributeError 로 죽으면서 사용자 발화 처리·종료 안내말·멈춤이 전부 중단됐다(사용자 보고 "발화 무반응·종료 안 됨·안내말 없음" 전부 이것). 임포트를 v4 사본으로 바꿨다. v4 사본은 v3 의 상위 집합이며 v3 파일은 무수정. 브랜치 범위 `145f5c6`..`abf7a21`, dev 재머지 대기.
