# 음성채팅 첫 인사말

> [!summary] 한 줄 요약
> 마이크 버튼을 누르면 사용자가 말하기 전에 관리자가 설정한 인사말을 AI가 먼저 발화하고 말풍선으로도 표시하는 기능. 본체 저장 → SQLite → 컨테이너 → 발화 + 말풍선까지 **E2E 검증 완료**. 서비스: [[AI음성]]

## 무엇을 했나

팀장 지시로 3개 레포에 걸쳐 배선했다. 관리자 페이지 [채팅화면설정 > 음성채팅 첫메시지]에 입력한 문구가 v4 세션 시작 시 자동 발화되고, 같은 문구가 봇 말풍선으로 화면에 타이핑된다.

| 구간 | 내용 |
|---|---|
| 본체 (Chatty_Project) | `voice_first_msg` 필드 수용 — 요청 모델 + SQLite 컬럼 자동 마이그레이션 + 조회 SELECT |
| AI_Pro_VOICE | `greeting.py` 로더(SQLite 직접 읽기 + HTML 정제) → 세션 metadata → OpenAI 응답 큐로 발화 + `voice_greeting.message` DataChannel 이벤트 |
| 프론트 (서버 작업본) | 이벤트 수신 → 말풍선 렌더 체인 연결 + 텍스트 첫 메시지와 분리 + 중복 말풍선 제거 |

## 무엇이 달라졌나

통화 시작 즉시 AI가 먼저 인사한다 — 발화는 OpenAI 응답 큐(`kind="greeting"`)로 나가고, 말풍선은 발화 트랜스크립트(`response.audio_transcript.*`) **단일 경로**로 타이핑된다.

- 저장소는 PostgreSQL이 아니라 **봇별 SQLite** `{ACCOUNT_DIR}/{upload_dir}/chatbot_config.db` — 컨테이너에 읽기 전용 마운트로 연결했다. 이 패턴이 이후 봇별 설정(음성선택 등)의 기준점이 된다.
- 음성 시작 세션에서는 텍스트용 "채팅 첫 메시지"가 뜨지 않는다 (`startedByVoice` 게이트).
- 컬럼이 아직 없는 계정에서는 기능만 조용히 비활성 — 배포 순서 자유.

## 왜

음성 채팅 진입 시 무응답 상태로 시작하는 UX를 개선하려는 팀장 지시. 인사말 문구는 봇마다 다르므로 관리자 설정으로 뺐다.

## 함정 (디버깅에서 확정)

- **환경 페어 일치** — dev 본체(9000)→`/NAS/data_dev` vs 운영 본체(7000)→`/NAS/data`. 컨테이너 `CHATTY_ACCOUNT_DIR`이 자기 환경 경로를 가리켜야 한다. 두 번 엇갈렸다.
- **`.env`는 컨테이너 재생성 시에만 반영** — `docker restart` 불충분, `compose up -d --build --force-recreate`.
- **중복 말풍선** — 전용 이벤트 렌더와 발화 트랜스크립트 렌더가 동시에 그렸다(콘솔 실측 `['voice-greeting', 'resp_*']`). 브릿지 `handleGreeting`을 no-op으로 바꿔 트랜스크립트 하나로 통일. 이벤트는 브릿지 미마운트 페이지의 모듈 직접 렌더 폴백용으로 유지.
- **Vue 템플릿 게이트** — 채팅 영역이 `hasAskedQuestion`으로 숨겨져 있어 어시스턴트-온리 경로에서 플래그를 세워야 말풍선이 보인다.
