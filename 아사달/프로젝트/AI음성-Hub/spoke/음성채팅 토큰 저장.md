# 음성채팅 토큰 저장

> [!summary] 한 줄 요약
> v4 통화의 문답 한 쌍을 계정 MariaDB 의 `AIPRO_CHAT_MESSAGE` 1행과 응답별 `AIPRO_API_USAGE_LOG` 행으로 파이썬이 직접 저장한다. main·dev 브랜치 커밋 완료, 푸시·dev 실통화 확인 전. 서비스: [[AI음성]]

## 무엇을 했나

DB 담당자가 `dev_user`·`testchatbot1` 에 AIPRO 테이블 3종을 만들고, 각 서비스가 파이썬에서 토큰을 저장하도록 요청했다. 음성은 **지금 기록되는 범위(짝이 맺어진 문답과 그 답변 토큰)만** 옮겼다.

| 테이블 | 쓰는 값 |
|---|---|
| `AIPRO_CHAT_MESSAGE` | 문답 1건 = 1행. `job_type='voice_chat'`, `content_type='audio'`, `request_id` 는 턴마다 서버 uuid4, `gen_params={"voice": ...}`, `contact_ip` 는 세션 생성 요청의 `x-forwarded-for` |
| `AIPRO_API_USAGE_LOG` | 답변에 든 Realtime 응답 1개 = 1행. 토큰은 제공자 값 그대로, `raw_usage` 에 usage 원문, `provider_request_id` 에 응답 id, `modality='realtime'` |
| `AIPRO_MEDIA_ASSET` | 쓰지 않음 |

```
response.done → 응답별 {id, status, usage} 를 답변과 함께 TurnLogger 로 운반
짝 맺음(_send_turn_record)
  ├ 브라우저: token_usage 합계(지금과 동일 → PHP → CHATING_PROCESS)
  └ UsageLog.save_turn → 백그라운드: 연결 → MESSAGE → USAGE executemany → commit
```

## 무엇이 달라졌나

프론트 변경 없이 v4 통화가 AIPRO 테이블에 쌓인다. 도구 턴은 한마디 응답과 답변 응답이 **USAGE 2행**이 되고, 행을 더하면 `CHATING_PROCESS` 에 저장되는 값과 같다. 테이블이 없는 DB 는 조용히 건너뛰므로 운영에 먼저 나가도 해가 없다.

## 왜

AIPRO 규약은 "호출 1회 = USAGE 1행", "total_tokens 직접 합산 금지" 다. 기존 음성 기록은 한마디 응답과 답변 응답 토큰을 더한 값 하나만 PHP 로 보내서 규약과 맞지 않았다. 담당자 답장으로 `job_type` 값은 예시이며 `voice_chat` 을 써도 된다고 확인했다.
