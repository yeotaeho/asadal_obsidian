# 음성채팅기록

> [!summary] 한 줄 요약
> 기획서 **V1.6(음성채팅기록)** 을 두 단계로 나눠, **1단계(텍스트 기록)는 저장·토큰·모델명 표시·짝 밀림 수정까지 dev 에서 돌고 있다.** 2단계는 `voice_audio` 컬럼·목록 재생을 먼저 놓고, **질문 + 답변(도구 전 한마디 포함)을 `_qa.wav` 한 파일로 NAS 에 남기는 녹음을 통화 경로에 연결했다**(2026-09-15, dev 사본 푸시·첫 통화 검증 대기). 키워드(#)는 보류 중. 서비스: [[AI음성]]

| ① 모델명 필터 | 채팅기록 화면의 모델명 셀렉트박스에 음성 모델 4종 추가 | 1 |

회장님 결정으로 **음성채팅기록 탭은 따로 만들지 않는다.** 기존 채팅기록 화면 하나에 음성 대화가 섞여 나오고 모델명으로 구분한다. 기획서 1페이지도 "채팅기록 메뉴에 음성사용기록이 함께 기록됩니다"로 같은 말을 한다.

기획 확정(2026-09-10)으로 **질문은 녹음, 답변은 기존 텍스트 채팅의 "음성" 버튼 경로(Google TTS)** 로 읽는다. 답변 소리는 저장하지 않는다.

## 왜 이렇게 작아졌나

조사해 보니 서버가 필요한 재료를 **이미 대부분 만들고 있었다.** 답변 전사는 `_capture_assistant_transcript` 가 세션별로 누적하고 `response.done` 에서 꺼내며, 질문 전사도 이미 뽑아 턴 버퍼에 넣고 있었다. 다만 그 결과가 **로그로만** 나갔다.

그래서 1단계에서 새로 만든 것은 **두 텍스트를 한 쌍으로 묶어 브라우저에 알리는 일 하나**뿐이다.

쓰는 컬럼이 전부 기존 컬럼이라 **스키마 변경이 없다.** 스키마의 유일한 정의는 본체 `dev/class.chatbot.php` `createTable()` 안의 DDL 문자열(봇당 테이블 6개, 채팅기록은 `$table_name5`)이고 ORM·엔티티 파일은 없다. 기존 봇 컬럼 추가(`ALTER TABLE`)는 코드 어디에도 없어 DBA 가 손으로 한다.

| 컬럼 | 값 |
|---|---|
| `text_data` · `type` | 질문·답변 전사, `q`/`a` |
| `model_name` | 실제 모델 ID. **이 값이 곧 음성 대화 판별자** |
| `session_id` | 음성 세션 UUID. 늘 NULL 이던 컬럼을 음성에서만 채운다 |
| `input_tokens` · `cached_tokens` · `output_tokens` · `total_tokens` | 답변 응답의 usage. 질문·답변 두 행에 같은 값 |
| `contact` · `created_at` · `parent_id` | PHP 가 채운다 |

## 무엇을 했나 (1단계)

```
[음성 서버]
  TurnLogger (v4/turn_log.py, 순수 동기)
    질문 전사 ─┐
              ├─ turn_id 일치 → 도착 순서(FIFO) 로 짝짓기
    답변 전사 ─┘   인사말·종료말·RAG 안내말은 응답 kind 로,
              │   도구 호출 응답의 한마디는 response.output 으로 제외
              → voice_chat.turn 통지 1건 (DataChannel, token_usage 동봉)

[브라우저 · 본체 dev/]
  webrtc_voice_module.js  case 'voice_chat.turn' → CustomEvent('voice-chat-turn')
  index2.js               persistVoiceChatTurn → process_add.php → 봇별 기록 테이블
```

`server_webrtc.py` 에는 훅만 얹었다. 세션 부착·해제, 답변 전사 전달, 사용자 전사 전달, 응답 kind 추적이 전부다. **답변 기록은 `response.done` 에서 확정**된다 — 전사 `.done` 은 버퍼를 완성본으로 바꾸기만 한다.

질문 전사에는 OpenAI `item_id` 를 함께 싣는다. 2단계가 녹음 파일을 질문에 붙일 때 쓰는 열쇠다. 서버 `turn_id` 는 GA 경로에서 전사가 늦게 오면 새로 발급돼 열쇠로 쓸 수 없다.

## 리뷰가 잡은 결함

리뷰 세 겹(태스크별·전체·Codex)이 **그냥 뒀으면 기능이 조용히 죽었을 결함 둘**을 잡았다.

**GA 이벤트 이름.** v4 기본 모델인 GA 는 답변 전사를 `response.output_audio_transcript.*` 로 보내는데, 서버의 네 판정 지점이 모두 `response.audio_transcript` 접두사만 받고 있었다. 운영 기본 경로에서 통지가 **0건**이었을 것이다. 프론트가 두 이름을 모두 분기하는 것이 실트래픽 근거였다. 접두사 상수 하나로 양쪽을 받게 했다. **dev 실측으로 이 수정이 맞았음이 확인됐다** — 통지가 턴마다 나왔다.

**델타 누적 오염.** 조각이 버퍼에 이미 있으면 버리는 검사(`raw not in current`)가 한국어에서 상시 발동해 버퍼를 훼손하고, `.done` 병합이 그 훼손본을 이어붙여 답변이 **두 배**로 저장됐다.

```
버퍼   : '구로구는 서울에 있습니다. 구 인구가 많습니다'       ← "로구는" 유실
저장   : '구로구는 서울에 있습니다. 구 인구가 많습니다구로구는 서울에 있습니다. 구로구는 인구가 많습니다.'
기대   : '구로구는 서울에 있습니다. 구로구는 인구가 많습니다.'
```

휴리스틱을 지우고 델타는 원문 그대로 잇게 했다. `.done` 이 완전한 전사를 싣고, 버퍼는 `.done` 이 오지 않는 끼어들기 경로에서만 쓰인다.

**끼어들기가 응답 kind 를 먼저 지움.** 대칭성을 이유로 `_handle_interruption` 에 pop 을 넣었더니, 취소된 RAG 안내말의 뒤늦은 정리가 kind 를 잃어 "잠시만 기다려 주세요"가 답변으로 기록됐다. Codex 가 잡았고 되돌렸다. **kind 는 `response.done` 의 flush 까지 살아 있어야 한다.**

그 밖에 넷을 더 고쳤다. `detach` 가 첫 await 뒤에 기록기를 닫아 재부착 경합 시 새 세션 기록이 영구 불능이 되던 것, 짝짓기 큐가 무한히 자라 답변 유실 1회로 이후 전체가 한 칸 밀리던 것, 양쪽 turn_id 가 모두 있고 다를 때도 교차 짝짓기하던 것, 비 v4 세션에도 기록기가 붙던 것이다.

## dev 실측이 잡은 결함

리뷰 세 겹이 못 본 것을 **첫 통화가 잡았다.** RAG 도구가 도는 턴마다 답변이 둘 들어와 그다음 짝부터 한 칸씩 밀렸다.

| 턴 | 질문 | 기록된 답변 | 실제 답변 |
|---|---|---|---|
| 3 | 여행지 하나 추천해줄래 | **좋아, 여행지 취향을 떠올리면서…** | 죄송하지만, 제공된 근거에서는… |
| 4 | 일본이나 하고 싶은데… | 죄송하지만, 제공된 근거에서는… | 도쿄, 교토, 오사카를… |

GA 모델은 `function_call` 을 내기 전에 **스스로 한마디** 한다. 자동 응답이라 kind 가 없어 `"final"` 이 되고, 전사 `.done` 이 `function_call` 보다 먼저 와서 그 시점엔 도구 호출인지 알 수 없다. 서버 안내말(`kind="tts"`)은 아니었다 — 그 경로는 호출자가 0건인 죽은 코드다.

기록 시점을 `response.done` 으로 옮기고 `response.output` 에 `function_call` 이 있으면 안내말로 본다. 끼어들기 경로도 같은 flush 를 쓰므로 기록 경로가 하나가 됐다 (`5061ebb`).

**두 번째 — 한 응답에 말 항목이 둘.** 재검증 통화에서 모델이 "좋아요, …골라볼게요." 서두와 긴 답변을 한 응답에 항목 둘로 냈다(도구 호출 없음). 전사 `.done` 은 항목마다 오므로 `.done` 마다 버퍼를 교체하던 코드는 마지막 항목만 남겼다. 이번엔 서두가 앞이라 긴 답변이 남았지만 순서가 반대였으면 긴 답변이 빠졌다. 항목별 완성 전사를 모아 `response.done` 에서 이어 붙이게 했다 (`7c8a7a0`).

같은 현상이 **화면에서는 반대로** 나타났다. 프론트가 `response.done` 에서 말풍선을 한 번 더 그리는데 그때 `response.output` 의 첫 항목만 꺼내 써서, 긴 답변이 다 그려진 뒤 서두 한 문장으로 되돌아갔다. `voice_webrtc_handler.js:606` · `voice_chat_bridge.js:347`, 담당자 전달.

## 목록의 빈 칸 — 토큰과 키워드

저장이 붙고 나니 목록에서 음성 행만 **키워드·입력·캐시·출력·합계 다섯 칸이 `-`** 였다. 두 무리는 경로가 전혀 다르다.

**토큰 네 칸은 `token_usage` 키 하나로 들어간다.** 텍스트 채팅은 `/ask` SSE 의 마지막 청크로 받아 저장 본문에 실어 보내고, `process_add.php` 가 질문·답변 두 행에 같은 값을 복사한다. 음성 서버는 `response.done` 마다 **같은 모양의 `token_usage` 이벤트를 이미 브라우저로 보내고 있었지만** 모듈에 분기가 없어 버려졌다.

그 이벤트를 프론트에서 주워 쓰는 대신 **서버가 기록 통지에 실어 보내게** 했다(`b4c719d`). 어느 응답이 기록되는 답변인지는 서버만 안다 — 도구 호출 응답도 usage 를 내므로 프론트가 받으면 어느 값이 그 질문의 것인지 가릴 수 없다. `response.done` 은 기록을 확정하는 자리이자 usage 가 실려 오는 자리라 인자 하나로 흘려보내면 끝이었다.

**키워드(#)는 컬럼이 아니라 `chat_process_keyword_map` 별도 테이블이다.** 재료는 `/ask` 가 RAG 청크·웹 결과에서 뽑아 Redis 에 10분 임시 저장하고, 저장 뒤 프론트가 `/chat/keywords/commit` 으로 커밋해야 행이 생긴다. 음성은 `/ask` 를 타지 않아 임시 키워드가 없고, 커밋은 **매 턴 404** 로 돌아와 콘솔 경고만 남겼다. 호출을 뺐다.

음성 키워드를 채우려면 shim 의 pgvector 검색에서 생략한 형태소 키워드 추출과 `SEARCH_TOKEN_LIST` 매핑을 본체에서 가져와야 한다. 1단계 범위 밖이라 기획 확인 대상으로 남긴다.

**모델명 칸의 "오픈AI 챗GPT-4.1" 은 DB 가 아니라 목록 페이지였다.** `chatlog.htm` 의 `get_model()` 이 텍스트 카탈로그 `modelList` 만 뒤지고 못 찾으면 그 문자열 리터럴을 돌려줬다. 음성 모델은 같은 카탈로그 표에서 `fication='voice'` 로 갈라져 `modelListVoice` 배열에 실리는데 참조가 0회였다. 두 배열을 합쳐 찾게 고쳤고 필터 셀렉트도 같이 고쳤다(2026-09-11). 경위는 [[AI음성 - 채팅기록 목록 모델명 매핑]].

목록의 `#` 은 `chat_process_keyword_map` 이 아니라 **일별 통계표 `chatbot_chatting_keyword_stat_daily`** 를 읽는다. 음성 키워드를 붙일 때 map 만 넣으면 안 보이고 통계표까지 채워야 한다. 본체 `_store_once` 를 그대로 타면 둘 다 들어간다.

## 2단계 — 필드 먼저, 녹음 나중

컬럼에 들어가는 값이 URL 문자열 하나라 녹음 없이도 배관을 끝까지 놓을 수 있다. 과장님 허락(dev·test 계정에 컬럼 추가 후 테스트, 운영은 완료 후 재논의)을 받아 순서를 바꿨다. 녹음은 통지에 `q` 를 붙이는 공급자로만 끼어든다.

**녹음은 질문과 답변 한 쌍이다(2026-09-15 2차 개정).** 기획서 V1.6 이 재생 대상을 "질문한 내용과 AI가 답변한 녹음본" 으로 적고, TTS 로는 채팅 음성 설정(cedar·marin 등)을 낼 수 없어 1차의 "답변은 재생 시 TTS" 를 뒤집었다. 답변은 다운링크 프록시가 브라우저로 내보낸 프레임을 담아 사용자가 들은 소리 그대로 남긴다.

```
[서버, 03a818b]   업링크 트랙 on_frame → 링버퍼, speech_started/stopped 의 audio_start_ms~audio_end_ms 로 질문 절단
                  다운링크 트랙 on_frame → 답변 (재생 창 안, 일시정지 무음 제외, 다음 발화·멈춤·종료말까지)
                  같은 턴 질문은 전사 도착 시점의 턴(set_turn)으로 합침
                  짝 맺음 + 답변 재생 완료 → 전용 스레드가 질문+무음+답변 _qa.wav 를 NAS 에 기록
                  voice_chat.turn 에 q:{path, t} (브릿지 _send_turn_record, TurnLogger 무변경)
[모듈]            q 가 있으면 apiVoiceUrl 로 절대 URL 을 만들어 voice_audio
[프론트]          persistVoiceChatTurn: voice_audio 가 있을 때만 message_q 에 키
[PHP 저장]        GetInsertSQL → voice_audio 컬럼 (무변경. 컬럼이 없으면 소리 없이 버림)
[목록]            learn_chatprocess_list.php q.* → chatlog.htm <audio> 하나로 ▶ ⏸ ■
                  삭제 전에 voice_audio 로 DELETE (실패해도 행 삭제 진행)
```

**컬럼은 두 갈래다.** 앞으로 만드는 봇은 `class.chatbot.php` `create_sql5` 의 DDL 이 전부 채우고, 기존 봇은 ALTER 스크립트가 채운다. `IF NOT EXISTS` 라 코드가 기존 표를 고치지 않는다. dev·test 는 `TABLE_SCHEMA IN ('dev_user','testchatbot1')` 로 범위를 묶는다. 표가 MyISAM 이라 ALTER 가 표를 복사하며 잠근다.

**저장 위치는 NAS 다.** dev `/NAS/data_dev/voice_records`, 운영 `/NAS/data/voice_records` 이고 컨테이너에는 그 하위 폴더만 쓰기로 붙인다. 경로는 서버 compose 에 직접 적었다(dev 반영 완료). dev 공유는 root 를 강등하지 않아 컨테이너 root 로 쓰기·삭제가 된다(실측). 본체가 `uploads` 를 `/static` 으로 공개하므로 그 밑에는 두지 않는다. 비밀키 `VOICE_RECORD_SECRET` 은 서버 `.env` 에 `openssl rand -hex 32` 로 새로 만들어 넣고 바꾸지 않는다.

**NAS 는 통화 경로에서 만지지 않는다.** 마운트가 `hard` 라 NAS 가 끊기면 입출력이 멈춘다. 녹음은 메모리에 모았다가 전용 스레드가 쓰고, 짝 못 맺은 쌍은 파일을 만들지 않는다. 개정 설계서 `docs/superpowers/specs/2026-09-09-voice-record-playback-design.md` §0.
