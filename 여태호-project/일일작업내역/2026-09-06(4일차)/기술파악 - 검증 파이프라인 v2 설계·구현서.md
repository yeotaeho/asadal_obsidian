# 검증 파이프라인 v2 설계·구현서

> [!summary] 한 줄 요약
> 디스코드 실발송 확인 뒤 키워드 관문의 한계를 실데이터로 짚고, 임베딩·LLM 선별·피드백 기반 v2 를 브레인스토밍 → 설계서(Codex 6회) → 구현서(Codex 2회) 로 확정했다. 기능: [[검증 파이프라인 v2]]

## 무슨 작업

**디스코드 첫 발송.** `.env` 의 채널 ID 가 서버 ID 였던 것을 잡고 새 `ai` 채널로 교정. 파이프라인 10배치(500건)를 돌려 실제 카드 **2건 발송**(uv 0.12.9, Anthropic SDK 1.3.0), push 1건은 무음 시간이라 QUEUED.

**키워드 관문 진단.** 하루 유입 약 650건 중 600건이 arXiv. 앞 9배치 450건이 전부 arXiv 라 LLM 호출 없이 탈락. 맥락 없음·새 용어 무시·한국어 제목의 세 결함을 실사례로 확인.

**대안 논의.** A LLM 선별 배치, B 임베딩 유사도, C 피드백 학습, D 소스별 정책. A+B+C 를 한 설계로, D 는 소스 확장 때. B 는 pg_trgm 중복 판정을 대체하되 "같은 사건(≥0.92)" 과 "같은 주제(≥0.80)" 를 구분. C 는 라벨이 하루 3건 수준이라 사례 주입·신뢰도 보정·주간 리포트·탐색 슬롯 순.

**설계서.** 브레인스토밍 스킬로 섹션별 승인을 받아 작성. Codex 리뷰 6회를 거치며 확정한 것: 단일 프로세스 전제 명시, HNSW 제거(정확 검색), 중복 쿼리 A/B 분리, 선별 실패 3층위, `llm_calls` 호출 전 예약 + 자문 잠금 단일 키, 쿼리 B 의 같은 소스 포함·집계 제외, 버전 토큰 집합, 자정 경계, 피드백 유니크.

**구현서.** 4단계 24태스크. 태스크마다 실패 테스트 → 구현 → 통과 → 커밋. Codex 2회에서 선별 재시도 예약 누락, 통합 테스트의 asyncpg vector 캐스트 불능, autoflush 로 첫 실패 폐기, 재임베딩 가드 부재 등을 잡아 반영.
