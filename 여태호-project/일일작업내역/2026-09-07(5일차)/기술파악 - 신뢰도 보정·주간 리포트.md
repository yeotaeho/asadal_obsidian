# 신뢰도 보정과 주간 리포트 (v2 4단계, 마무리)

> [!summary] 한 줄 요약
> 소스 신뢰도 베이즈 보정과 주간 튜닝 리포트를 만들고, 상세 문서 3종을 v2 로 다시 써서 검증 파이프라인 v2 4단계를 전부 마쳤다. 기능: [[검증 파이프라인 v2]]

## 무슨 작업

**신뢰도 보정.** `pipeline/trust.py` 의 `adjust_trust(base, useful, useless)` 가 `(10×base + 👍) / (10 + 👍 + 👎)` 를 [0.2, 1.0] 으로 자른다. 사전 가중치 10 은 라벨 10건이면 원래 값과 데이터가 반반이라는 뜻. 점수 관문은 `sources.trust_adjusted` 가 있으면 그것을, 없으면 `trust_score` 를 쓴다. `precision`·`score_band`·`band_table` 도 여기 순수 함수로.

**주간 리포트.** `scripts/weekly_report.py --days N [--apply]`. 표 7개: 관문별 깔때기, 탈락 사유 상위 10, 소스별 발송·👍·👎·정밀도, importance 별, 점수 구간별(탐색 포함), 선별 relevance 구간 vs 판정, 저관련도 선별 이유 표본. 발송 코호트 기준이라 피드백은 도착 시점 무관하게 세고, 신뢰도 보정만 최근 30일 라벨. `--apply` 는 활성 소스의 `trust_adjusted` 를 쓰고 커밋 뒤에만 반영됐다고 말한다.

**실DB 첫 실행.** 탈락 사유 상위: stale 3,994 · 점수 미달 417 · no_keyword 235(v1 잔여) · whitelist_stale 24(v1 잔여) · 판정 false 12 · exclude 3. 선별 relevance 0.4 구간 7건 중 판정 true 2·false 2, 0.8 구간 2건 중 true 1. 라벨은 아직 0 이라 정밀도 표는 비어 있다.

**문서.** `런타임 플로우`·`파일·함수 레퍼런스`·`폴더·파일 역할 지도` 를 v2 3국면·예약·탐색 기준으로 전면 재작성. `결정 기록` 에 v2 절 추가.

## 왜
