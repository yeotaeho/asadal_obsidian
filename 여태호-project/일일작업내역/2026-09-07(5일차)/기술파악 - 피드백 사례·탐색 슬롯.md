# 피드백 사례 주입과 탐색 슬롯 (v2 3단계)

> [!summary] 한 줄 요약
> 임베딩이 가까운 👍/👎 항목을 선별·판정 프롬프트에 사례로 붙이고, 점수 관문 바로 아래 항목을 하루 1건 판정해 🧪 카드로 보내는 탐색 슬롯을 넣었다. 기능: [[검증 파이프라인 v2]]

## 무슨 작업

**최근접 피드백 사례.** `pipeline/feedback.py` 의 `nearest_feedback` 이 항목 벡터와 코사인 ≥ 0.75 인 피드백 항목을 거리순으로 k 건 찾아 `👍 "제목" · 👎 "제목"` 한 줄로 만든다. 피드백은 항목당 1건이라 조인이 곧 최신 판정이다. 자기 자신은 제외한다.

**프롬프트 주입.** 선별은 항목마다 2건을 사용자 블록의 항목 줄 아래에, 판정은 3건을 `유사 피드백:` 줄로 붙인다. 시스템 블록(정책·캐시)은 건드리지 않는다. 판정 프롬프트에 "유사 피드백은 importance 와 worth_notifying 에 강하게 반영" 한 줄을 더했다.

**탐색 슬롯.** `Level.EXPLORE` 를 추가하고 발송 잡 끝에 `_explore` 를 붙였다. 무음 시간이 아니고 오늘 탐색 발송이 없으면, `DROPPED` 이며 Summary 가 없고 점수가 [임계값−0.10, 임계값) 이며 24시간 이내이고 **마지막 결정 행이 score 탈락** 인 최고점 항목을 잠근다. 본문 보강(`body_for_judge`) → `reserve_call("explore")` → 판정 → Summary 저장. true 면 `🧪 실험 · 경계 항목` 머리말로 silent 발송하고 `SENT`, false 면 Summary 만 남겨 재판정을 막고 슬롯은 소진하지 않는다. 발송 잡의 `now` 도 항목마다 새로 읽어 자정 경계를 맞췄다.

## 왜

피드백은 보낸 것에만 붙는다. 잘못 버린 것은 라벨이 없어 파이프가 자기 편향을 강화한다. 하루 1건 경계 항목을 실험으로 보내 경계 라벨을 모은다. 사례 주입은 학습 없이 검색만으로 개인화를 시작하는 가장 싼 방법이다.
