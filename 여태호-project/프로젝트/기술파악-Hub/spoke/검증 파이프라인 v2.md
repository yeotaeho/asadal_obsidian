# 검증 파이프라인 v2

> [!summary] 한 줄 요약
> 키워드 목록 관문을 **정책 기반 관문**으로 바꾼 작업. 임베딩으로 중복·관련을 판정하고, LLM 선별 배치가 관심 정책을 직접 읽어 관련도를 매기며, 👍/👎 가 다음 판정에 사례로 되먹임되고 소스 신뢰도를 보정한다. **4단계 전부 완료** (2026-09-07). 브랜치 `feat/verification-v2`, `main` 머지 대기. 서비스: [[기술파악]]

## 왜

실데이터에서 키워드 관문의 결함 셋이 확인됐다.

| 결함 | 실제 사례 |
|---|---|
| 맥락 없음 | 안전성 해석 논문이 `vector` 로, 3D 장면 논문이 `reasoning` 으로 통과 |
| 새 용어 무시 | 목록에 없는 새 모델명은 `no_keyword` 로 탈락. 알림기의 존재 이유와 정면충돌 |
| 한국어·영상 | YouTube 제목엔 영문 키워드가 없어 관문을 못 넘음 |

관심 정책은 이미 `rules.yaml` 문장으로 있었는데 그것을 읽는 관문이 맨 끝 판정 LLM 뿐이었다.

## 무엇을 했나

```
수집 → 적재 → 임베딩(1회 저장) → NEW
1국면  stale(72h) → ① 중복(코사인 ≥0.96, 생존자 기준) → ② exclude 만
2국면  ③ LLM 선별 25건 배치 (관련도 0~1 + 이유, 최근접 피드백 2건 주입)
3국면  ④ 점수(src·rel·hot·multi·fresh ≥ 0.45, src 는 보정값 우선) → ⑤ 보강 → ⑥ 판정 (피드백 3건 주입)
발송   기존 정책 + 🧪 탐색 슬롯 1건/일
주간   weekly_report.py 로 표를 보고 rules.yaml 조정, --apply 로 소스 신뢰도 보정
```

| 단계 | 결과 |
|---|---|
| 1 임베딩·벡터 중복 | 마이그레이션 0003, Voyage 1024차원, 백필 4,656건, `pg_trgm` 삭제, 임계값 표본 보정 **0.96/0.88** |
| 2 정책·선별·3국면 | `rules.yaml` 재구조화(`extra=forbid`), exclude 전용 규칙, `rel` 점수 항, 전역 stale, `reserve_call` 자문 잠금 예약, 선별 배치(실패 3층위), 3국면, 화이트리스트·키워드 관문 삭제, SDK `max_retries=0` |
| 3 피드백·탐색 | `nearest_feedback`(≥0.75) 주입, `Level.EXPLORE` 탐색 슬롯(마지막 결정이 score 탈락인 경계 항목), 발송 잡 항목별 시각 |
| 4 보정·리포트 | `adjust_trust` 베이즈 평활 → `trust_adjusted`, `weekly_report.py` 표 7개, 비활성 소스 배치 제외 |

## 무엇이 달라졌나

- 실배치에서 선별이 캐너리 릴리즈 0.3·기능 릴리즈 0.6~0.8 로 갈랐다. 키워드 없어 죽던 항목이 관련도로 통과한다.
- 백로그 3,963건 정리에 **LLM 호출 0**. stale 가드가 선별 앞이라서다.
- 모든 LLM 호출이 `llm_calls` 예약 뒤에만 나간다. 실패한 호출도 상한에 잡힌다.
- 피드백은 항목당 1건. 다음 선별·판정에 사례로 들어가고 소스 신뢰도를 보정한다.
