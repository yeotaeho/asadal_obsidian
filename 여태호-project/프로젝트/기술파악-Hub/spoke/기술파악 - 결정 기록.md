# 기술파악 - 결정 기록

> [!summary] 한 줄 요약

## 아키텍처 (구현도 2.2절)

| 결정 | 채택 | 기각한 대안 | 이유 |
|---|---|---|---|
| 큐 | **Postgres `status` + `FOR UPDATE SKIP LOCKED`** | Redis / Celery / RQ | 단일 사용자·소량 트래픽. 인프라가 하나 줄고 상태 조회·디버깅이 SQL 한 줄 |
| 스케줄러 | **APScheduler (AsyncIOScheduler)** | cron / Temporal | 소스별 5분~6시간 주기를 코드로 관리. 프로세스 내 실행이라 배포가 단순 |
| DB | **Neon (서버리스 Postgres)** | VM 위 자체 Postgres 컨테이너 | 운영·백업 부담 없음, 브랜치로 dev/운영 분리, `pg_trgm` 지원 |
| 중복 제거 | **제목 유사도 (pg_trgm)** | 임베딩 유사도 | 대부분의 중복은 같은 URL 또는 거의 같은 제목. 임베딩은 4단계에서 재검토 |
| 크롤링 | **trafilatura (보강 단계만)** | WaterCrawl / Crawl4AI | MVP 보류. JS 렌더링이 필요해지면 `sources/` 플러그인으로 검토 |
| 푸시 채널 | ~~텔레그램 봇 선행~~ → **디스코드 봇** (2026-09-03 사용자 결정) | 앱 + FCM 직행 / 웹훅만 | 핵심 가치는 파이프라인. 어댑터 추상화 덕에 채널 교체가 쌌다. 아래 "디스코드 전환" 참고 |
| 본문 보강 시점 | **점수 통과 후, LLM 직전** | 수집 시점 | 탈락할 항목의 원문 페이지까지 긁지 않기 위해 |
| 패키지 구조 | **파이프라인 단계별 레이어드** | 헥사고날 | 지금 규모에 층을 더 나눌 이유가 없음 |

## Neon 연결·첫 수집에서 결정한 것 (2026-09-02)

| 결정 | 채택 | 기각한 대안 | 이유 |
|---|---|---|---|
| asyncpg TLS | **`ssl.create_default_context()` 를 `connect_args` 로 직접 전달** | URL 에 `ssl=require` 문자열 | asyncpg 가 `~/.postgresql/root.crt` 를 읽다 비ASCII 홈 경로에서 `OSError` 로 죽고 asyncpg 가 잡지 않는다. 부수 효과로 인증서 검증이 켜진다 |
| 외부 유입 문자열 컬럼 | **`items.author`·`external_id` 를 `text`** | `varchar(n)` + 잘라 넣기 | arXiv 저자 목록이 300자를 넘겼다. Postgres 에서 `varchar(n)` 은 이득이 없다 |
| 적재 실패 처리 | **`store_items` 를 savepoint 로 감싸 실패 경로에 포함** | `fetch` 만 감싼 채 유지 | 적재 예외가 새면 `fail_count` 가 안 오르고 나머지 소스까지 죽는다 |
| Anthropic 피드 | **커뮤니티 미러 + `allowed_hosts: [anthropic.com]`** | 직접 스크래핑 / 제외 | 공식 RSS 없음. 서드파티라 외부 링크는 버린다 |

## 파이프라인 첫 실행에서 결정한 것 (2026-09-02)

| 결정 | 채택 | 기각한 대안 | 이유 |
|---|---|---|---|
| 화이트리스트와 점수 관문 | **`always_pass_source` 는 점수 관문 우회, 48h 이내만** | 그대로 점수화 / 한국어 키워드 / 우회 소스 목록 분리 | YouTube 28건 중 27건이 키워드 0개 → 어떤 신뢰도로도 0.45 를 못 넘는다. 거르는 일은 LLM 이 맡는다(사용자 결정). 백필 230건은 신선도 가드로 막는다 |
| 규칙 통과 시 매칭 키워드 | **화이트리스트·저장소 경로도 키워드를 돌려준다** | 빈 목록 유지 | GitHub 200건이 점수 통과 0 → 96 |
| arXiv `trust_score` | **0.5 유지** | 0.3 | 실측 통과율 10%(61/609). 0.3 은 0건이 되는 이진 선택(사용자 결정) |
| dedupe 기준 | **살아남은 항목(SCORED·QUEUED·SENT)만** | 상태 무관 → DROPPED·FILTERED_OUT 제외 → +FAILED 제외·NEW 유지 → **NEW 도 제외** | 세 번 뒤집혔다. 규칙에서 떨어질 A(NEW) 가 자기 힘으로 통과할 B 를 먼저 죽이는 반례로 최종 확정 |
| 다중 소스 신호 | **`mention_count` 가 점수화 시점에 유사 제목의 다른 소스 수를 직접 센다** | `cluster_id` 연결 수 | dedupe 기준을 좁히면 연결이 안 생겨 multi 가 죽는다. 직접 세면 순서·상태와 무관 |

## 디스코드 전환에서 결정한 것 (2026-09-03)

| 결정 | 채택 | 기각한 대안 | 이유 |
|---|---|---|---|
| 디스코드 연동 방식 | **봇 (Bot 토큰 + 채널 ID + 공개 키)** | 웹훅 URL 하나 | 웹훅 메시지에는 버튼을 달 수 없어 피드백(4단계 개인화의 입력)이 빠진다. 웹훅은 서명 검증·`pynacl` 이 없어 더 쌌지만 기능을 포기해야 했다 |
| 텔레그램 코드 | **어댑터로 남긴다** (`send_ops_alert` 만 제거) | 삭제 | `Notifier` 프로토콜의 대안 구현. 채널을 되돌릴 때 비용이 0 |
| 피드백 콜백·상대 시각 | **`notify/base.py` 로 이동** | 텔레그램 모듈에서 import | 채널 공통 로직이 한 채널 모듈에 있으면 결합이 생긴다 |
| 재시도 | **명시 루프 — 네트워크·5xx·429 만, 4xx 즉시 실패** | tenacity 로 모든 예외 3회 | 401·403 을 반복하면 디스코드가 봇을 제한한다 |
| 429 처리 | **`retry_after` 를 자르지 않고 존중. 30초 초과·3회 소진은 `RateLimited` 로 배치 중단 + 프로세스 전역 게이트** | 30초 상한으로 잘라 재시도 / 실패로만 기록 | `retry_after` 는 "다음 요청" 까지의 대기다. 잘라서 재시도하거나 다음 항목을 바로 보내면 제한을 다시 밟는다. 게이트는 뒤로만 민다(`max`) — 동시 요청의 짧은 429 가 긴 대기를 덮어쓰지 않게 |
| global / 라우트별 429 구분 | **하지 않는다** | 별도 게이트 | 발송·운영 알림이 전부 같은 채널 라우트라 게이트 하나가 상위집합 |
| 링크 URL 검증 위치 | **`store_items`(적재)에서 http(s) 아니면 거부 + 버튼은 스킴·512자 통과 시만** | 발송 직전만 | 모든 수집 경로가 지나는 한 곳이 근본. 본문 보강도 이 URL 을 쓴다. 버튼 쪽은 방어 |
| 마크다운 이스케이프 범위 | **`*_~`|\[]()#>-`** | 서식 문자만 | `allowed_mentions` 는 멘션만 막고 링크 마스킹·헤딩은 못 막는다. `\-` `\#` 는 그대로 보인다 |
| User-Agent | **`DiscordBot (https://github.com/yeotaeho/trend, 0.1.0)`** | httpx 기본 | 디스코드 문서 요구. 없으면 Cloudflare 차단 가능 |

## 리뷰에서 나왔지만 반영하지 않은 것

| 지적 | 판단 | 이유 |
|---|---|---|
| `notifications(item_id, channel)` 유니크 제약 | **기각** | 중복 *발송* 을 막지 못하고 *기록* 만 막는다. outbox 로 바꿀 때 함께 |
| GitHub repo 별 커서 | **보류** | 첫 페이지 20건으로 사실상 누락 없음 |
| 본문 보강의 리다이렉트 최종 호스트 재검증 | **완료 (2026-09-14, 소스 확장 1차)** | `enrich_body` 가 홉마다 목적지(사설·링크로컬)를 검사한다. 아래 "소스 확장 1차" 참고 |
| 우회 소스 목록(`score_bypass_sources`) 분리 | **기각** | 신선도 가드가 실제 문제(백필)를 더 정확히 겨눈다 |
| `mention_count` trigram 비용 | **후속** | MVP 규모에선 수용. 커지면 `EXPLAIN ANALYZE` |
| 다중 워커 시 A·B 동시 SCORED | **후속** | 단일 프로세스 MVP 에선 없음 |
| 적재 거부(잘못된 URL)를 `decisions` 에 기록 | **기각** | `decisions.item_id` 가 필요한데 적재 전이라 항목이 없다. 로그(`ingest.rejected_url`)로 충분 |
| 디스코드 429 게이트를 프로세스 밖(DB)에 공유 | **후속** | 워커 분리 전엔 프로세스 하나. 분리할 때 함께 |

## 검증 파이프라인 v2 — 1·2단계 (2026-09-06)

키워드 목록 관문을 정책 관문으로 바꾸면서 v1 의 여러 결정이 뒤집혔다. 아래 표의 "뒤집은 v1 결정" 이 위쪽 표에서 무효가 된 행이다.

| 결정 | 채택 | 뒤집은 v1 결정 / 기각한 대안 | 이유 |
|---|---|---|---|
| 중복 판정 | **임베딩 코사인 (Voyage 1024차원)** | v1 의 `pg_trgm` 제목 유사도 0.6 을 대체 | 표현이 다르면 trigram 이 놓치고 언어를 못 넘는다. 같은 소식의 다른 제목·한영 교차를 벡터가 잡는다 |
| 벡터 검색 | **72h 창 정확 검색, 인덱스 없음** | HNSW | 창 안 2,000행이라 밀리초. 근사 검색은 상태·시간 필터와 결합하면 최근접을 놓친다 |
| 중복 vs 관련 | **중복 0.96(생존자 기준)·관련 0.88(상태 무관) 두 쿼리** | 단일 임계값 | 중복 오판은 항목을 잃고 관련 오판은 점수만 오른다. 정밀한 쪽만 좁게 |
| 임계값 | **0.96 / 0.88** (표본 보정) | 설계 초안 0.92 / 0.80 | 0.90~0.95 는 전부 다른 사건(조코딩 다른 영상 0.93, Next.js 다른 릴리즈 0.91), 0.80~0.85 는 arXiv 주제 이웃 |
| 포함 판단 | **LLM 선별 배치 (관련도 0~1)** | v1 의 `include_keywords`·`include_repos` 관문 삭제 | 키워드는 맥락을 못 보고 새 용어를 놓친다. 정책 문장을 선별이 직접 읽는다 |
| 화이트리스트 | **삭제** | v1 의 `always_pass_sources`·`whitelist_max_age_hours` | 선별이 있으면 우회할 이유가 없다. YouTube·GitHub 도 같은 선별을 지난다 |
| 신선도 가드 | **전역 72h, 선별 앞** | 화이트리스트 전용 48h | 백필·오래된 항목이 선별 예산을 쓰지 않게. 모든 소스 공통 |
| 점수 kw 항 | **rel 항 (선별 관련도)** | `w_kw` (키워드 개수) | 관련도가 신뢰도와 합산돼 "저신뢰+고관련 통과, 고신뢰+무관 탈락" 이 한 식에 |
| 선별·판정 관계 | **선별 → 점수 → 판정** | 점수 → 선별 | 저신뢰 소스의 새 용어를 아무도 읽기 전에 버리지 않으려고 |
| LLM 호출 상한 | **호출 전 `llm_calls` 예약 행 (자문 잠금)** | v1 의 `summaries` 롤링 24시간 집계 | 실패한 호출을 못 세면 폭주 루프를 못 막는다. 상한의 존재 이유가 그 경우 |
| SDK 재시도 | **`max_retries=0`** | SDK 기본 2회 | 재시도는 예약 없이 나가 상한을 깬다. 기반 실패는 NEW 로 남기고 다음 잡이 새 예약 |
