# 기술파악 - 런타임 플로우

> [!summary] 한 줄 요약
> 프로세스가 뜨고 나서 항목 하나가 소스에서 디스코드까지 가는 경로를, 예외 경로와 트랜잭션 경계까지 포함해 단계별로 적었다. 수집과 관문 ①~④ 는 Neon 에서 실전 확인됐고, 발송·피드백은 채널 설정 뒤 확인한다. 서비스: [[기술파악]]

## 기동

```
uvicorn app.main:app
  └ lifespan 진입
      ├ configure_logging()                     structlog JSON
      └ start_scheduler()                       SCHEDULER_ENABLED=true 일 때만
          ├ sync_sources()                      config/sources.yaml → sources 테이블
          └ add_job × (활성 소스 수 + 2)
              ├ source:<이름>   interval = poll_interval_sec
              ├ pipeline        interval = 120초
              └ notify          interval = 180초
```

전부 `max_instances=1`, `coalesce=True` 다. DB 연결은 import 시점에 `app/db/session.py` 가 만든다 — `sslmode` 는 URL 에서 떼고 `ssl.create_default_context()` 를 직접 준다.

## 1. 수집 — `run_source(source_id)`

```
session_scope() 열기
  Source 조회 → 비활성이면 0 반환
  try:
    source.fetch(last_polled_at)                 ← 네트워크
    savepoint 시작
      store_items()                              http(s) 아닌 URL 은 거부(로그) → ON CONFLICT DO NOTHING
    savepoint 커밋
  except:
    fail_count += 1, last_error 기록             ← last_polled_at 전진 안 함
    5회째면 커밋 후 디스코드 운영 알림 (실패·RateLimited 는 로그만)
    0 반환
  last_polled_at = now, last_error = None, fail_count = 0
커밋
```

**GitHub 만 예외** — `since` 를 무시하고 매번 최근 20건을 다시 본다. **미러 피드** — `rss:anthropic` 은 `allowed_hosts` 로 외부 링크를 버린다. **URL 스킴** — `javascript:`·`data:` 는 적재 단계에서 막는다. 모든 수집 경로(RSS·GitHub 폴링·웹훅)가 `store_items` 를 지나므로 이 한 곳이면 된다.

## 2. 웹훅 — 즉시 경로

```
POST /webhook/github
  HMAC-SHA256 검증 (X-Hub-Signature-256)         실패 → 401
  release 이벤트만 → release_to_item() → store_items() → items(NEW)
```

이후는 `run_pipeline` 이 **최대 2분** 뒤에 이어받는다.

## 3. 관문 — `run_pipeline()`

```
session_scope() 열기
  budget = LLM_DAILY_CAP − 최근 24h summaries 수
  budget ≤ 0 → 즉시 0 반환
  _claim_batch()  50건, FOR UPDATE SKIP LOCKED, 최신순

  for 항목:
    budget ≤ 0 → break
    item_id = item.id                            ← 롤백 뒤 item 속성을 읽으면 MissingGreenlet
    savepoint 시작
      ① dedupe    72h 내 similarity > 0.6 인 SCORED·QUEUED·SENT 항목 → FILTERED_OUT(dup)
      ② rules     exclude 우선 → always_pass → include_repo → include_keyword. 탈락 → FILTERED_OUT
      ③ scoring   always_pass ─ 48h 이내 → 우회 / 그 외 → DROPPED(whitelist_stale)
                  나머지 ─ trust·kw·hot·multi·fresh 가중합 ≥ 0.45. multi 는 유사 제목의 다른 소스 수
      ④ enrich    body < 300자면 원문 받아 trafilatura (실패해도 계속)
      ⑤ llm       messages.parse 1회 → summaries. false → DROPPED / true → SCORED
    savepoint 커밋
커밋
```

각 단계는 `decisions` 에 남는다. 항목 하나가 던지면 그 savepoint 만 롤백한다. 실전 수치와 ①③ 의 근거는 [[기술파악 - 결정 기록]].

## 4. 발송 — `run_notify()` → 디스코드

```
session_scope() 열기
  visited = {}
  최대 20회 반복:
    _claim_one(visited)                          LIMIT 1, FOR UPDATE SKIP LOCKED
    없으면 break
    decide(importance, now)
      ├ importance ≤ 2               → feed_only  → notifications(feed) 기록, SENT
      ├ 무음 시간(23~08 KST)의 push    → quiet_hours → QUEUED (다음 잡)
      ├ 하루 상한(15) 초과             → SILENT
      └ 그 외                         → PUSH / SILENT

    DiscordNotifier.send()
      build_payload: content(마크다운 이스케이프) + 버튼 3개 + allowed_mentions.parse=[]
                     SILENT 면 flags=4096(@silent). 링크 버튼은 http(s)·512자 이내일 때만
      _call("POST", /channels/{id}/messages)
        게이트 확인 ─ _blocked_until 전이면 네트워크 없이 RateLimited
        최대 3회: 네트워크 오류·5xx 는 백오프, 429 는 게이트 세우고 retry_after 대기,
                 4xx 는 즉시 RuntimeError. 429 가 30초 초과·3회 소진이면 RateLimited

    RateLimited  → 기록 없이 break                ← 항목 탓이 아니다. 다음 잡이 같은 항목부터
    그 외 예외   → notifications(error) 기록, FAILED
    성공         → notifications(message_id) 기록, SENT
    커밋                                          ← 항목 하나 = 트랜잭션 하나
```

**게이트** — 프로세스 전역 `_blocked_until`(monotonic). 429 의 `retry_after` 는 "다음 요청" 까지의 대기라 그 시각 전엔 어떤 디스코드 요청도(발송·운영 알림) 보내지 않는다. 뒤로만 민다(`max`) — 동시 요청의 짧은 429 가 긴 대기를 덮어쓰지 않게. 워커가 여럿이면 프로세스마다 따로 세워지므로 분리 전에 공유 저장소로 옮겨야 한다.

**왜 한 건씩 잠그나** — 20건을 잠그고 루프에서 커밋하면 첫 커밋에서 나머지 락이 풀린다. **왜 `visited`** — `QUEUED` 는 여전히 `PENDING` 이라 제외하지 않으면 같은 항목만 잡는다.

이 단계는 아직 실전 미실행 — 봇 서버 초대와 채널 ID 교정이 남았다.

## 5. 피드백 — 디스코드 인터랙션

```
사용자가 👍/👎 클릭
  → Discord → POST /webhook/discord            (Interactions Endpoint URL, 배포 후 등록)
      Ed25519 검증: X-Signature-Ed25519 / X-Signature-Timestamp, 메시지 = timestamp + 원문 바디
        공개 키 비어 있음·헤더 없음·검증 실패 → 401
      type 1 (PING)  → {"type": 1}              ← URL 저장 시 디스코드가 보내는 확인
      type 3 (버튼)  → custom_id "fb:useful:123" 파싱 → feedback INSERT + 커밋
                     → {"type": 4, data: {content, flags: 64}}   누른 사람에게만 보이는 답장
```

3초 안에 응답해야 한다. 별도 API 호출 없이 응답 본문으로 바로 답한다. 텔레그램 콜백(`/webhook/telegram`)은 대안 어댑터로 남아 있다.

## 상태 전이

```
NEW ──dup/no_keyword──▶ FILTERED_OUT
NEW ──규칙 통과──▶ (점수 또는 화이트리스트 우회) ──미달/stale──▶ DROPPED
                        └─통과──▶ (LLM) ──false──▶ DROPPED
                                        └─true──▶ SCORED ──상한/무음/RateLimited──▶ QUEUED·SCORED 유지
                                                         └─발송──▶ SENT / FAILED
```

## 동시성

| 항목 | 지금 |
|---|---|
| 프로세스 | 1개 (FastAPI + APScheduler 같은 프로세스) |
| 잡 겹침 | `max_instances=1` |
| 큐 | `items.status` + `FOR UPDATE SKIP LOCKED` |
| 커넥션 | 잡 하나 = 세션 하나, Neon pooled, `statement_cache_size=0`, TLS 컨텍스트 직접 주입 |
| 디스코드 429 | 프로세스 전역 게이트. 운영 알림과 발송이 공유 |
| 워커 분리 시 | `decide()` 하루 상한 집계, dedupe "먼저 SCORED 되는 쪽", 429 게이트가 경합·미공유. 분리 전에 설계 |
