# 기술파악 - 파일·함수 레퍼런스

> [!summary] 한 줄 요약
> 파일별 공개 심볼, 호출 체인, 그리고 손댈 때 밟기 쉬운 함정들. 서비스: [[기술파악]]

## 파일 지도

| 구분 | 파일 |
|---|---|
| **전용** (한 곳에서만 씀) | `sources/youtube.py`, `api/health.py`, `scripts/run_job.py` |
| **공용** (여러 곳이 의존) | `config.py`, `schemas.py`, `log.py`, `db/models.py`, `db/session.py` |
| **재사용 자산** | `sources/rss.py`(YouTube 가 재사용), `sources/github_release.release_to_item()`(폴링·웹훅 공유), `pipeline/normalize.py`(ingest 가 사용), `notify/telegram._call()`(발송·콜백응답·운영알림 공유) |

## 호출 체인

```
APScheduler
 ├ run_source(id) ─ build_source ─ <Source>.fetch ─ fetch_url
 │                └ store_items ─ to_row ─ normalize_url ─ url_hash
 ├ run_pipeline() ─ _llm_calls_today
 │                └ _claim_batch
 │                   └ _process ─ find_cluster
 │                              ├ apply_rules ─ find_keywords / _excluded_domain
 │                              ├ mention_count
 │                              ├ score_item ─ hotness / freshness
 │                              ├ llm.enrich_body
 │                              └ llm.judge ─ messages.parse
 └ run_notify() ─ _claim_one
                └ decide ─ level_for / in_quiet_hours / push_count_today
                └ TelegramNotifier.send ─ render ─ relative_time
                                        └ _call

FastAPI
 ├ GET  /health           ─ session_scope
 ├ POST /webhook/github   ─ verify_signature ─ release_to_item ─ store_items
 └ POST /webhook/telegram ─ parse_feedback_callback ─ answer_callback
```

## 파일별 심볼

### `app/config.py`

| 심볼 | 설명 |
|---|---|
| `Settings` | `.env` 시크릿. `database_url` 만 필수, 나머지는 기본값 |
| `SourceConfig` | `sources.yaml` 한 항목. `config` 는 타입별 자유 dict |
| `Rules` | `rules.yaml` 전체 — 키워드, `interests`, `ScoringConfig`, `NotifyConfig` |
| `get_settings()` / `get_rules()` / `get_source_configs()` | 전부 `lru_cache(1)` |
| `reload_configs()` | 캐시 비우기. `rules.yaml` 핫리로드용 (아직 호출부 없음) |

### `app/schemas.py`

`Category`(7종) · `ItemStatus`(7종) · `Stage`(rule/score/llm) · `Level`(push/silent/feed) · `NormalizedItem` · `LLMVerdict`.

### `app/db/session.py`

| 심볼 | 설명 |
|---|---|
| `to_asyncpg_url(url)` | psql 문자열 → asyncpg. `sslmode` → `ssl`, `channel_binding` 등은 제거 |
| `engine` / `SessionLocal` | import 시점에 생성. `DATABASE_URL` 없으면 import 자체가 실패 |
| `session_scope()` | 성공 시 커밋, 예외 시 롤백. **잡 하나 = 세션 하나** |

### `app/sources/base.py`

| 심볼 | 설명 |
|---|---|
| `Source` | `name` + `async fetch(since)` 프로토콜 |
| `register(type_name)` | 데코레이터. 팩터리를 레지스트리에 등록 |
| `build_source(cfg)` | 타입 → 인스턴스. 미등록 타입은 `KeyError` |
| `retryable(exc)` | 네트워크 오류·429·5xx 만 True |
| `fetch_url(url, headers)` | GET + 3회 지수 백오프 |

### `app/pipeline/`

| 심볼 | 설명 |
|---|---|
| `normalize_url(url)` | 소문자화, 추적 파라미터 제거, **파라미터 정렬**, `www.`·트레일링 슬래시 제거 |
| `url_hash(normalized)` | SHA-256 hex |
| `strip_html(text)` | 태그 제거 + 엔티티 해제 + 공백 정규화 |
| `to_row(source_id, item)` / `store_items(...)` | `ON CONFLICT DO NOTHING` + `RETURNING id` |
| `find_cluster(session, title, exclude_item_id)` | 72h · similarity > 0.6 → `coalesce(cluster_id, id)` |
| `mention_count(session, item_id)` | 나를 대표로 삼는 중복 수 + 1 |
| `apply_rules(rules, ...)` → `RuleResult` | `passed`, `reason`, `matched_keywords` |
| `score_item(cfg, ...)` → `ScoreResult` | `score`, `passed`, `breakdown` |
| `enrich_body(url)` | 실패 시 `None`, 예외 안 던짐 |
| `judge(rules, ...)` → `LLMResult` | `verdict`, `model`, `tokens_in/out` |

### `app/notify/`

| 심볼 | 설명 |
|---|---|
| `level_for(importance)` | ≥4 push / 3 silent / ≤2 feed |
| `in_quiet_hours(cfg, now)` | 자정을 넘기는 구간 처리 |
| `push_count_today(session, cfg, now)` | KST 자정 이후 성공 push 수 |
| `decide(session, cfg, importance, now)` → `Verdict` | `level`(None 이면 보류) + `reason` |
| `render(item, summary, source_name, now)` | HTML 이스케이프된 메시지 본문 |
| `feedback_callback_data` / `parse_feedback_callback` | `fb:useful:123` 왕복 |
| `TelegramNotifier.send(...)` | 성공 시 `message_id` 문자열 |
| `answer_callback` / `send_ops_alert` | 토스트 응답 / 운영 알림 |

## 손댈 때 규칙·함정

### 트랜잭션

- `session_scope()` 안에서 **외부 호출을 하고 나서 커밋하면 안 된다.** 뒤에서 하나가 실패하면 이미 나간 알림까지 롤백돼 다시 발송된다. `run_notify` 는 항목마다 커밋한다.
- `run_pipeline` 의 항목 루프는 `begin_nested()` savepoint 안에 있다. 새 단계를 넣을 때 이 안에 넣어야 실패 시 함께 롤백된다.
- `session.commit()` 은 `FOR UPDATE` 락을 푼다. 여러 행을 잠근 채 루프에서 커밋하지 마라.

### 수집기

- 새 소스는 `sources/__init__.py` 에 **import 를 추가해야** 레지스트리에 등록된다. 파일만 만들면 `build_source` 가 `KeyError` 를 던진다.
- `fetch()` 가 예외를 던져야 `last_polled_at` 이 전진하지 않는다. 내부에서 삼키면 그 구간을 영구히 놓친다.
- `since` 를 신뢰할 수 있는 건 소스 전체가 한 요청으로 끝날 때뿐이다. 여러 요청으로 쪼개지면 부분 실패가 누락으로 이어진다.

### 정규화·중복제거

- `normalize_url` 결과는 **해시 전용**이다. 실제 요청은 원본 `item.url` 로 한다(파라미터 정렬이 서버 동작을 바꿀 수 있으므로).
- `find_cluster` 는 `similarity()` 를 쓰므로 **Postgres 전용**이다. sqlite 로는 테스트할 수 없다.

### 텔레그램

- `_call` 은 봇 토큰을 URL 에 넣는다. **httpx 예외를 그대로 밖으로 던지면 토큰이 문자열에 섞여 DB·로그에 남는다.** 예외를 갈아끼우는 코드를 지우지 마라.
- `render()` 는 `parse_mode: HTML` 을 쓴다. LLM 이 만든 문자열을 넣을 때는 반드시 `escape()` 를 거쳐야 한다.

### LLM

- `messages.parse(..., output_format=LLMVerdict)` 의 `parsed_output` 은 타입상 `Optional` 이라 `assert` 로 좁힌다.
- 모델 ID 는 날짜 접미사 없는 `claude-haiku-4-5`. `.env` 의 `LLM_MODEL` 로 덮어쓸 수 있다.
- 하루 상한은 `jobs/pipeline.py` 가 관리한다. `pipeline/llm.py` 는 상한을 모른다.

### 설정

- YAML 로더는 `lru_cache` 라 **프로세스 재시작 전까지 변경이 반영되지 않는다**. `reload_configs()` 가 준비돼 있지만 아직 부르는 곳이 없다.
- `sources.yaml` 이 진실이다. 여기서 빠진 소스는 다음 기동 때 `enabled=false` 가 된다(삭제는 안 함).
