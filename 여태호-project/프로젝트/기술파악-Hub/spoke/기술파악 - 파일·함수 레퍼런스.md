## 데이터 모델 — 테이블·컬럼

7개 테이블 전부 `db/models.py`. 상태의 단일 진실 원천이자 큐다(`items.status` + `FOR UPDATE SKIP LOCKED`).

### sources

기동 시 `scheduler.sync_sources` 가 `config/sources.yaml` 을 동기화하고, 수집 잡이 결과를 갱신한다.

| 컬럼 | 역할 | 쓰는 곳 | 읽는 곳 |
|---|---|---|---|
| `name` `type` `config` `poll_interval_sec` | YAML 정의. type 은 rss·github_release·youtube | `sync_sources` | `collect.run_source` |
| `trust_score` | YAML 신뢰도 | `sync_sources` | 점수 관문 (`trust_adjusted` NULL 일 때) |
| `trust_adjusted` | 👍/👎 베이즈 보정값. NULL 이면 미보정 | `weekly_report.py --apply` | `pipeline._judge` 우선 사용 |
| `enabled` | YAML 에서 빠지면 false | `sync_sources` | 수집·파이프라인 배치 제외 |
| `last_polled_at` | 마지막 성공 수집. 다음 `fetch(since)` | `run_source` 성공 | 수집기 |
| `last_error` `fail_count` | 연속 실패. 3회째 운영 알림 | `run_source` 실패 | 운영 확인 |

### items

| 컬럼 | 역할 | 쓰는 곳 |
|---|---|---|
| `source_id` `external_id` `url` `url_normalized` `url_hash` `title` `summary_raw` `author` `published_at` `raw` | 수집 원본. `url_hash` 는 추적 파라미터 제거 뒤 SHA-256, 유니크. `raw.metrics` 에 stars·points | `ingest.store_items` |
| `fetched_at` | 적재 시각 | DB 기본값 |
| `embedding` `embedding_model` | 적재 시점 `제목+본문 300자` 1024차원. deferred, 비교는 SQL | `embedding.embed_pending` |
| `status` | NEW → FILTERED_OUT / DROPPED / SCORED → QUEUED / SENT / FAILED | 파이프라인·발송 잡 |
| `cluster_id` | 중복·관련 상속 뿌리. 독립이면 자기 id | `pipeline._gate` |
| `score` | 점수 관문 합계. 탐색 후보 선택에 재사용 | `pipeline._judge` |
| `category` | 판정 LLM 분류 | `_judge` `_explore` |

### decisions

| 컬럼 | 역할 |
|---|---|
| `stage` | rule · triage · score · llm |
| `passed` | triage 는 "선별을 마쳤다". 통과 여부는 score 가 정한다 |
| `score` | 그 시점 `items.score` 스냅샷 |
| `details` | rule: `reason`(stale·dup·exclude·dedupe_skipped)·`matched`. triage: `relevance` `reason` `kind` `batch_id`. score: `breakdown`(src·rel·hot·multi·fresh·kind) `triage_reason`. llm: `importance` `tags` `enrich_failed` `explore` |

쓰기 `_record`(세 국면)·`_explore`. 읽기 `_existing_relevance`(선별 캐시), `_triage_error_count`, `_explore_candidate`(마지막 결정이 score 탈락), 리포트.

### summaries

`item_id` 가 기본키. 있으면 다시 판정하지 않는다.

| 컬럼 | 역할 |
|---|---|
| `title_ko` `summary_ko` `tags` | 발송 카드 본문 |
| `importance` | 1~5. ≥4 push, 3 silent, ≤2 feed |
| `worth_notifying` | false 면 DROPPED. 발송 쿼리는 true 만 |
| `model` `tokens_in` `tokens_out` | 비용 추적 |

쓰기 `_judge` `_explore`. 읽기 `_claim_one`, `nearest_feedback`(사례 제목), 리포트.

### notifications

| 컬럼 | 역할 |
|---|---|
| `channel` | discord |
| `level` | push · silent · feed(이력만) · explore |
| `sent_at` | 오늘(Asia/Seoul) push 상한·탐색 1건 집계 기준 |
| `message_id` | 디스코드 메시지 id. 리액션 폴링이 항목을 찾는 키 |
| `error` | 실패 사유. 있으면 항목 FAILED |

쓰기 `run_notify` `_explore`. 읽기 `push_count_today`, `_explore_sent_today`, `sync_feedback`, 리포트.

### feedback

| 컬럼 | 역할 |
|---|---|
| `item_id` | 유니크. 다시 누르면 덮어쓴다 |
| `verdict` | useful · useless |
| `created_at` | upsert 때 갱신. 신뢰도 보정 "최근 30일" 창 기준 |

쓰기 웹훅 두 곳·리액션 폴링(전부 `upsert_feedback` 경유). 읽기 `nearest_feedback`, 리포트.

### llm_calls

| 컬럼 | 역할 |
|---|---|
| `kind` | triage · judge · explore. 예산 triage 60, judge 300(explore 포함), explore 3 |
| `batch_id` | 호출 UUID. triage 결정 행 `details.batch_id` 와 이어진다 |
| `called_at` | DB 시각. 오늘 범위와 같은 값 |

쓰기·읽기 모두 `reserve_call` 뿐 (+ 리포트).

## DB 접근 함수 레퍼런스

세션을 여는 진입점은 `jobs/*.run_*`, `api/*`, `scripts/*` 뿐이고 `reserve_call` 만 자기 세션을 연다. 나머지는 전부 `session` 을 인자로 받는다.

| 함수 | 호출자 | 입력 | 하는 일 | 호출 | 변경 | 반환 |
|---|---|---|---|---|---|---|
| `scheduler.sync_sources` | `start_scheduler`, `run_job.py sync` | 없음 | `config/sources.yaml` 을 sources 에 upsert, YAML 에 없는 소스는 `enabled=False`. YAML 이 단일 진실이고 DB 는 사본 | `get_source_configs` | sources INSERT/UPDATE | 활성 Source 목록 |
| `collect.run_source` | 스케줄러(소스별 주기), `run_all_sources` | source_id | 소스 읽기 → `fetch(last_polled_at)` → savepoint 안 `store_items` → 새 id 임베딩 → 성공/실패 기록 | `build_source` `store_items` `embed_pending` `send_ops_alert` | items, sources(`last_polled_at`·`last_error`·`fail_count`) | 새 적재 건수 |
| `ingest.store_items` | `run_source`(savepoint), `api/github` | session, source_id, `list[NormalizedItem]` | URL 스킴 검사 → `to_row` → 배치 내 url_hash 중복 제거 → INSERT … ON CONFLICT (url_hash) DO NOTHING RETURNING id | `is_web_url` `to_row` | items INSERT | 새 id 목록 (기존이면 빈) |

**잠금 단위가 잡마다 다르다.** 파이프라인은 50건을 한 번에 잠그고 배치 끝에 커밋하지만, 발송은 `_claim_one` 으로 한 건씩 잠그고 항목마다 커밋한다. 발송에서 여러 건을 한 번에 잠그면 첫 커밋에 나머지 잠금까지 풀려 워커를 늘렸을 때 같은 카드가 두 번 나간다.

## DB 접근 구조

한 파일에 모아 관리하지 않는다. `app/db/` 는 **기반과 단일 경로가 필요한 것만** 갖는다.

| `app/db/` | 이유 |
|---|---|
| `session.py` 엔진·`session_scope` | 연결 규칙(Neon pgbouncer, TLS)이 한 곳 |
| `models.py` `types.py` | 스키마의 단일 정의. Alembic 도 이걸 본다 |
| `budget.py` `reserve_call` | 상한의 원자성이 "유일한 예약 경로" 에 달려 있다 |
| `feedback.py` `upsert_feedback` | 웹훅 두 곳 + 리액션 폴링이 같은 upsert 를 써야 한다 |

쿼리는 **그 쿼리를 쓰는 모듈이 갖는다**. 벡터 중복 SQL 은 `pipeline/dedupe.py`, 사례 SQL 은 `pipeline/feedback.py`, 임베딩 갱신은 `pipeline/embedding.py`, 적재는 `pipeline/ingest.py`, 잠금 쿼리는 각 잡(`_claim_batch` `_claim_one` `_explore_candidate`), 상한 카운트는 `notify/policy.py`. 세션은 잡(또는 API 핸들러·스크립트)이 열어 넘기고, 커밋 단위도 잡이 정한다(파이프라인은 배치 끝, 발송은 항목마다, 탐색은 자체). 구현도 2.2절의 "헥사고날 기각, 파이프라인 단계별 레이어드" 결정의 결과다.

## 손댈 때 규칙·함정

### 벡터·임베딩

- **벡터를 raw SQL 로 삽입하지 마라.** `update(Item).values(embedding=list)` 하나가 유일한 경로다.
- `item.embedding` 속성을 파이썬에서 읽지 마라. deferred 라 `MissingGreenlet`. 존재 여부는 `select(Item.embedding.is_not(None))`.
- `embedding_model` 비교는 `is_distinct_from`. `!=` 는 NULL 을 놓친다.
- 모델을 바꾸면 백필이 끝날 때까지 파이프라인이 스스로 멈춘다.
- 무료 등급은 RPM 3·TPM 약 1만. 배치 64 이하, 백필 20초 간격.

### 예약·상한

- **LLM 을 부르는 모든 경로는 `reserve_call` 뒤에 있어야 한다.** 선별 재시도도 새 예약. SDK 재시도는 꺼져 있다(`max_retries=0`).
- 예약은 독립 세션이다. 배치 트랜잭션 안에서 부르지 말고, 배치가 롤백돼도 예약 행은 남는다는 걸 전제로 한다.
- "오늘" 은 DB `now()` 를 한 번 읽어 범위와 `called_at` 에 같이 쓴다.

### 파이프라인

- 1국면·3국면은 항목별 savepoint, 2국면은 배치 단위다. 항목 실패 카운트는 `session.add` **전에** 센다.
- 배치 파싱 실패와 pydantic 검증 실패는 항목 탓이 아니다(`TriageBatchError`, 1회 재시도). 항목 실패는 "응답은 유효한데 idx 누락·범위 밖" 뿐이다.
- `Kind` 를 바꾸면 `rules.yaml` 의 `kind_weights` 키와 선별 프롬프트 목록을 같이 바꾼다. 옛 `decisions` 행은 `other` 로 복원되므로 마이그레이션은 필요 없다.
- 선별 결과는 `decisions` 에 남으므로 판정 예산이 바닥나 NEW 로 남은 항목은 다음 잡에서 호출 없이 재사용된다.
- 탐색 후보 서브쿼리는 `aliased(Decision)` + `correlate(Item)` 이어야 한다.

### 수집·발송·피드백

- `retryable` 에 4xx 를 넣지 마라. 401·404 는 다시 해도 같고, 반복하면 상대가 차단한다.
- 리액션 시드 실패로 `send` 가 예외를 올리면 안 된다. 메시지는 이미 나갔고, FAILED 로 만들면 다음 잡이 같은 카드를 또 보낸다.
- `sync_feedback` 은 바뀐 판정만 upsert 한다. 매번 쓰면 `created_at` 이 밀려 신뢰도 보정 30일 창이 어긋난다.
- 리액션 읽기는 봇의 Read Message History, 시드는 Add Reactions 권한이 필요하다.
- 429 게이트는 프로세스 단위다. 워커를 늘리면 공유 저장소로 옮긴다.

### 설정

- `rules.yaml` 은 `extra="forbid"`. 키를 추가하려면 `config.py` 모델에도 넣는다.
- 정책 문장은 `policy.interests`·`not_interested`. `focus_stack` 은 힌트일 뿐 관문이 아니다.
- dedupe 임계값(0.96/0.88)은 표본 보정값. 바꾸려면 `calibrate_dedupe.py` 표본을 먼저 본다.

### 테스트

- 통합 테스트는 `TEST_DATABASE_URL`(Neon dev) 이 있을 때만 돈다. 루트 conftest 가 `DATABASE_URL` 을 덮어쓴다.
- 테스트마다 이벤트 루프가 새로 생긴다. 통합 conftest 가 매 테스트 뒤 `engine.dispose()`.
- 테스트 헬퍼가 세션을 `async with` 로 감싸 반환하면 닫힌 세션이 온다. `SessionLocal()` 을 열어 돌려주고 호출자가 닫는다.
- 디스코드 429 테스트는 실제 sleep 을 쓴다. Windows 타이머는 최대 15ms 일찍 깨므로 `retry_after` 는 0.1 이상.
