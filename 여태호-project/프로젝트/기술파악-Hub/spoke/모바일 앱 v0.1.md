# 모바일 앱 v0.1

> [!summary] 한 줄 요약
> Gas Town 컨보이(tr-dun)가 09-24 에 만든 플러터 앱과 앱 API v1 을 브랜치 하나(`feat/mobile-app-v0.1`)로 모았다. 로그인·온보딩을 뺀 화면 03~11 이 fixture 로 전부 돌고 테스트 **260개 통과**. main 병합 전이다. 서비스: [[기술파악]]

## 무엇을 했나

컨보이 작업이 브랜치 5개에 흩어져 있었다. `integration/mobile-app-v0.1-dun` 에는 백엔드 앱 API v1(B1~B9), 플러터 기반, 화면 03·07·08, FCM 이 들어 있었고, 나머지 화면은 폴리캣 브랜치 4개에 병합되지 않은 채 남아 있었다.

이 넷을 integration 위에 병합했다. 충돌은 매번 라우터 import 와 라우터 테스트의 fixture 오버라이드 두 곳이었다. 병합 뒤 쓰이지 않게 된 자리표시 화면(`placeholder_page.dart`)은 지웠다.

## 디자인 ↔ 백엔드 갭

갭 검토는 컨보이가 `docs/design/gap-matrix.md` 로 이미 해 두었다. 기준 커밋은 지금 `origin/main` 과 같은 `93439be` 라 그대로 유효하다.

**디자인에 있는데 백엔드에 없던 것**은 B1~B9 로 채웠다. 사용자 식별자(`users`·`user_id`), 설정 덮어쓰기(`user_prefs`), taxonomy 12개와 선별 `topics`, `cluster_daily_cap`·`delivery_by_importance`·`explore_enabled`·채널 설정, 찜·폴더, 주간 리포트 저장, 기기 등록·FCM, 소스 `display_name` 이 여기에 든다.

**백엔드에 있는데 디자인에 없던 것**은 앱 쪽에 더했다. 걸러짐 관문 `stale`·`cluster_dup`, HN 용 `커뮤니티` 소스 섹션, 설정 루트 화면, 표시 이름 편집, 관문별 보기, 리포트 상세가 그렇다.

**아직 없는 것**은 검색(피드·걸러짐·찜), 🔔 알림 화면, 소스 추가(`+`)다. 누르면 `준비 중` 스낵바만 뜬다.

## 무엇이 달라졌나

Codex 리뷰가 낙관적 쓰기에서 P2 세 건을 찾았다. 요청이 겹칠 때 실패한 요청이 자기 이전 스냅샷 전체로 되돌려, 이미 저장된 다른 변경까지 화면에서 지우는 문제였다.

| 화면 | 문제 | 고친 방식 |
|---|---|---|
| 05 알림 설정 | 늦게 실패한 저장이 뒤에 성공한 저장을 지움 | 저장을 하나씩 보내고 가장 나중 저장의 결과가 화면을 정함 |
| 06 수집 소스 | 한 소스 실패가 다른 소스 토글까지 되돌림 | 실패한 그 소스만 되돌림 |
| 11 찜 되돌리기 | 다시 찜은 됐는데 메모 PATCH 실패 시 목록에서 빠짐 | 다시 찜한 즉시 목록에 넣음 |

세 경우를 재현하는 테스트를 먼저 수정 전 코드에서 실패시키고 고쳤다. 재리뷰는 지적 없이 통과했다.

## 왜

사용자가 "디자인을 보고 플러터로 앱 화면을 구현해 보라"고 요청했다. 확인해 보니 같은 디자인 파일로 만든 구현이 원격에 이미 있었고, 사용자가 새로 만들기 대신 **기존 작업 이어받기**를 골랐다.

## 개발 환경 함정

- **flutter_tester 는 한글 임시 경로를 못 연다.** `C:\Users\여태호\...\Temp` 아래 커널 파일을 읽다가 `Could not prepare isolate` 로 모든 테스트가 로드 실패한다. `TEMP=C:\tmp\fltemp` 로 바꾸면 된다.
- 플러터를 3.47.5 로 올린 뒤 첫 실행은 Dart SDK 를 교체한다. 안드로이드 스튜디오의 dart 프로세스가 SDK 폴더를 잡고 있으면 교체에 실패하니 스튜디오를 닫는다.
- 플랫폼 폴더가 android·ios 뿐이다. 화면 확인은 임시 사본에 web 을 붙여 fixture 로 빌드해서 했다.
