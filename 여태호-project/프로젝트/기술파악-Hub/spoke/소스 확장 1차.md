# 소스 확장 1차

> [!summary] 한 줄 요약
> HN·Reddit·X 등 후보를 실측해 고른 1차 묶음. 새 소스보다 먼저 파이프라인 병목 셋(같은 URL 재관측 유실·보강 SSRF·첫 폴링 백로그)을 고치고, **Hacker News 프론트 페이지**와 **HF Daily Papers** 수집기, RSS 4개를 더했다. 브랜치 `feat/source-expansion-1`, **PR #5 머지 대기**. 서비스: [[기술파악]]

## 무엇이 달라졌나

점수식의 `hot`·`multi` 항이 처음으로 0 이 아니게 됐다. 지금까지는 `metrics` 를 채우는 소스가 GitHub prerelease 플래그뿐이고 같은 URL 은 두 번째 소스에서 오면 조용히 버려졌다.

Neon dev 실행: 소스 **15개** 빌드, HN **30/30**, HF Papers **50/46** (기존 arXiv **4건**에 upvotes 병합), 파이프라인 배치 2회 정상. family 적용 뒤 arXiv 재폴링에서 교차 등재 멘션 **0건**.

테스트 **131 → 176** (통합 13). Task 별 스펙·품질 리뷰 6회, 전체 브랜치 리뷰 5라운드, Codex 범위 리뷰 2회.

## 왜

허브의 "소스 확장 — HN·Reddit·Trending·X" 가 미착수였다. 실측하니 X 는 2026-02 무료 티어 폐지, Reddit 은 OAuth 승인 티켓이 필요해 둘 다 지금은 못 붙인다. 대신 무인증으로 되는 HN·HF Papers 를 골랐다. 코드를 읽어 보니 새 소스의 가치인 `hot`·`multi` 신호가 적재 충돌에서 새어 나가고 있어 그 병목을 먼저 고쳤다. 조사 상세는 설계서 2장.

리뷰에서 설계가 세 번 바뀌었다. arXiv 교차 등재가 multi 를 만드는 문제는 `family` 로, 되살림 조건은 "값이 바뀌면" → "근접 구간" → **"마지막 결정 기준 이득"** 으로. 상세는 [[기술파악 - 결정 기록]].
