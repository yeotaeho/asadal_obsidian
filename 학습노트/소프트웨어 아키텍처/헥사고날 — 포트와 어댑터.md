# 헥사고날 — 포트와 어댑터

> [!summary] 한 줄 요약
> 헥사고날 아키텍처(= **Ports and Adapters**)는 비즈니스 로직을 DB·HTTP·Kafka 같은 **외부 기술과 분리**하는 구조다. 도메인은 인터페이스(Port)만 알고, 실제 기술 구현(Adapter)이 그 뒤에 꽂힌다.

## 구조

```
             REST API
                ↓
            [Adapter]
                ↓
             [Port]
                ↓
        ┌──────────────┐
        │   Domain     │
        │ Application  │
        └──────────────┘
                ↓
             [Port]
                ↓
            [Adapter]
                ↓
        PostgreSQL / Kafka
```

- **Port** — 핵심 애플리케이션이 외부와 연결되기 위한 **인터페이스**.
- **Adapter** — 그 Port를 실제 기술로 **구현**한 것.

```java
// Port — 도메인이 아는 것은 여기까지
public interface UserRepository {
    User findById(Long id);
}

// Adapter — 기술은 바깥에서 갈아 끼운다
public class JpaUserRepositoryAdapter implements UserRepository { }
```

그래서 PostgreSQL을 MongoDB로 바꿔도 **Domain은 거의 영향을 받지 않는다**. 유지보수와 테스트가 중요한 시스템에서 강점을 갖는다.

## 어댑터 패턴 그 자체

Adapter는 헥사고날에서 자주 등장하지만, 원래는 독립적인 **디자인 패턴**이다. 목적은 **서로 호환되지 않는 두 인터페이스를 연결하는 것**.

```
        PaymentPort
             ↑
      ┌──────┴───────┐
 TossAdapter   KakaoPayAdapter
      │              │
   Toss API      KakaoPay API
```

핵심 코드는 `PaymentPort`만 바라보므로 **특정 결제 서비스에 종속되지 않는다**. 결제사를 추가할 때 어댑터 하나만 늘리면 된다.
