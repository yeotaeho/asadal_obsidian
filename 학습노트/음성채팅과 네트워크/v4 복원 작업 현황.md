# v4 복원 작업 현황

> [!summary] 한 줄 요약
> v4가 무너진 세 가지 이유([[v3와 v4 아키텍처]])를 각각 제거하면서, **v3는 절대 건드리지 않는 방식**으로 되살리는 작업. 2026-08-06 기준 Task 1~3 완료(브랜치 2개), Task 4~7과 프론트 배포·실기기 검증이 남았다.

## 타임라인

| 시점 | 사건 |
|---|---|
| 2026-07-13 | v4 롤백 (PR #593) — 사유: "모바일에서 [음성] 버튼을 눌러도 시작 안 됨" |
| ~2026-08-05 | 롤백 원인 조사, ICE 진단 도구 제작, 모바일 실기기 검증, 복원 계획 수립 |
| 2026-08-05 | 격리 복원 계획서 작성, 브랜치 작업 |

## 완료된 작업

**조사**
- 롤백 사유를 git 이력 + 인수인계 문서로 추적
- 프론트 소스 위치 발견 — Gitea `Ji-Hwan/frontend`의 `chat/voice/` (조직 저장소가 아닌 개인 저장소)
- ICE 진단 도구로 모바일 실기기 검증 → 가설 2개 기각 (TURN 부재, candidate 없는 offer)
- 5초 지연 원인 규명 + 해결 실측: **5,004ms → 6ms** ([[aiortc와 서버측 WebRTC]])

**구현 — 브랜치 2개, 전부 main 기준**

`feat/v4-isolated-restore` (9커밋):

```
① ICE 5초 지연 제거               ← 선행 조건
② v4 패키지 복원 (아직 미등록)
③ 로그 레벨 정상화
④ 유실된 버그수정 2건 복원
⑤ 그 안의 Critical 2건 추가 수정   ← 리뷰가 잡아냄
⑥ event loop 픽스 복원 (호출부 16곳 전수)
⑦ 회귀 방지 가드 테스트
```

`fix/v3-router-chat-id-guard-main` (1커밋) — 조사 중 발견한 운영 v3의 버그 수정.

**핵심 원칙**: v3 라우터를 **한 줄도** 건드리지 않았다. 롤백의 근본 원인(v3 하이재킹)을 반복하지 않기 위해서다. 리뷰 단계마다 `git diff`로 검증했다.

## 남은 작업

**v4 복원 태스크 (계획서 Task 4~7)**

| 태스크 | 내용 |
|---|---|
| 4 | 오디오 트랙 주입 배관 (`audio_track_cls`를 세션별로 주입) |
| 5 | 좀비 세션 스위퍼 복원 ← **모바일 직결** ([[운영에서만 터지는 문제들]]) |
| 6 | v4 라우터 등록 ← **여기서 처음 노출**. `ENABLE_VOICE_V4=on`일 때만 |
| 7 | 통합 스모크 테스트 |

**현재는 v4 코드가 들어와 있지만 어디에도 등록되지 않아 동작 변화가 0이다.** Task 6까지 가야 실제로 켜지고, 그마저도 환경변수 게이트 뒤에 있다.

**그 다음**
- **프론트 배포** — 백엔드에 v4를 올려도 운영 프론트가 호출하지 않는다. 프론트 정본 위치·배포 절차가 팀 확인 대기 중
- **모바일 실기기 검증** — 셀룰러(LTE/5G)에서
- **동시성 부하 측정** — 5초를 없앴어도 세션당 PeerConnection 2개 ([[aiortc와 서버측 WebRTC]]). 워커-세션 불일치 이슈도 검증 필요 ([[gunicorn 멀티워커 구조]] 함정 ③)

**배포 시 주의** (계획서에서)
- 선행 브랜치 `fix/v4-ice-gathering-latency`가 dev에 머지된 뒤 시작
- 활성화 후 **한 번에 한 세션씩** 테스트 — 2026-08-05에 연속 호출로 dev 앱이 응답 불능에 빠진 전력
- 필터 파라미터(`min_utterance_duration_ms=1000`, `barge_in_ms=1000`)는 실사용 적합성 미검증
