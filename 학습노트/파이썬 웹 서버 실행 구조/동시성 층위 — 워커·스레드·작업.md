# 동시성 층위 — 워커·스레드·작업

> [!summary] 한 줄 요약
> **워커는 프로세스, 요리사는 스레드, 냄비는 작업이다.** 프로세스 하나에 요리사는 보통 한 명이고, 그 한 명이 냄비 수백 개를 번갈아 돌린다. 그래서 **워커 수와 동시 처리 인원은 관계가 없다.**

## 왜 헷갈리나

"워커"라는 말이 층위마다 다른 것을 가리키기 때문이다 ([[프로세스와 스레드]]의 같은 지적).

여기에 더해 **"동시에 여러 개를 처리한다"는 말이 두 가지 완전히 다른 방식**을 뭉뚱그린다. 스레드를 여러 개 쓰는 방식과, 스레드 하나가 작업을 번갈아 잡는 방식이다. 파이썬 웹 서버는 **후자**를 주로 쓴다.

## 4층 구조

```
서버 (물리 장비)
│
├── 프로세스 = gunicorn 워커        ← 여러 개 (운영). 메모리 비공유
│   │
│   └── 스레드 1개  (요리사)        ← 이벤트 루프를 돌리는 주역
│       │
│       └── 이벤트 루프
│           ├── 작업 A (냄비 1)     ← 코루틴. 수백~수천 개
│           ├── 작업 B (냄비 2)
│           └── 작업 C (냄비 3)
│
└── (보조) 스레드 풀               ← 동기 함수를 대신 처리
```

| 층 | 무엇 | 개수 |
|---|---|---|
| 프로세스 | gunicorn 워커 | 설정한 만큼 (운영 N개, dev 1개) |
| 스레드 | 이벤트 루프를 돌리는 일꾼 | 프로세스당 보통 **1개** |
| 작업 | `async` 코루틴 | **수백~수천 개** |

**한 프로세스 안에 워커가 여럿 있을 수는 없다.** 워커가 곧 프로세스다. 한 프로세스 안에 여럿 있을 수 있는 것은 **스레드**다.

## 냄비 비유

요리사 한 명이 이렇게 일한다.

```
냄비 1: 물 끓는 중       → 기다려야 하니 손 뗌
냄비 2: 재료 볶기         → 지금 이걸 함
냄비 3: 오븐에 넣어둠     → 기다려야 하니 손 뗌
냄비 4: 소스 젓기         → 다음에 이걸 함
```

**냄비는 스레드가 아니라 작업이다.** 냄비가 20개로 늘어도 요리사는 한 명이다.

웹 서버 일의 대부분은 **기다리는 시간**이다. DB 응답, OpenAI 응답, 파일 읽기. 그동안 CPU 는 놀고 있으니 다른 요청을 처리하면 된다. `await` 가 바로 **"여기서 손 떼고 다른 냄비 보러 감"** 이라는 표시다.

냄비 하나에 요리사 한 명씩 붙이는 방식이었다면 동시 접속 500명에 스레드 500개가 필요하다. 스레드마다 메모리를 먹고 OS 전환 비용도 붙어 확장이 안 된다.

## 두 방식의 비교

| | 멀티스레드 | 이벤트 루프 |
|---|---|---|
| 구성 | 요리사 4명, 각자 냄비 1개 | 요리사 1명, 냄비 20개 |
| 전환 주체 | **OS** 가 번갈아 CPU 에 올림 | **코드가 스스로** `await` 에서 넘김 |
| 전환 비용 | 있음 (컨텍스트 스위칭) | 거의 없음 |
| 약점 | 스레드 수만큼 메모리 | **한 작업이 손을 안 떼면 전부 정지** |

## 이게 실전에서 터진 순간

v4 의 ICE 수집은 **`await` 없이 5초를 잡아먹는 동기 블로킹**이었다. 손을 뗄 지점이 없으니 요리사가 그 냄비 앞에 못 박힌다.

```
정상:      기다리는 동안 다른 냄비를 본다   → 다른 요청도 처리됨
ICE 5초:   5초간 그 자리에 붙박이          → 그 프로세스의 모든 요청 정지
```

음성만 멈추는 게 아니라 **같은 프로세스가 처리하던 `/ask` 채팅도, 챗봇 API 도 전부** 멈춘다.

**dev 는 uvicorn 단독이라 요리사가 한 명뿐이었다.** 세션 한두 건으로 앱 전체가 즉사했고, 2026-08-05 에 실제로 그렇게 멈췄다. 요리사가 여러 명이었다면 나머지가 다른 주문을 받아 **오히려 더 버텼을 상황**이다 ([[aiortc와 서버측 WebRTC]]).

## 보조 스레드 풀

FastAPI 에서 엔드포인트를 `async def` 가 아니라 그냥 `def` 로 쓰면, 그 함수는 **이벤트 루프를 막지 않도록 별도 스레드로 보내진다.** 요리사가 "이건 오래 걸리니 옆방 사람한테 맡기자" 하는 것과 같다.

블로킹 코드를 async 안에서 부를 때 `run_in_executor` 를 쓰는 것도 같은 장치다. **ICE 5초 같은 문제의 일반적인 회피책**이기도 하다 — 다만 v4 는 STUN 자체를 꺼서 5초를 없애는 쪽을 택했다.
